# Web Dropzone 1.0.0-rc03 — Release Notes

**Released:** 2026-11-22 · **Pre-release** (`npm install @keenmate/web-dropzone@rc`)

These notes cover the changes since **1.0.0-rc02**, the last version on npm. They are the first
release notes for this package; for earlier versions read the
[CHANGELOG](https://github.com/KeenMate/web-dropzone/blob/prod/CHANGELOG.md). Both packages ship
in lockstep, so this one file covers `@keenmate/web-dropzone` (the elements) and
`@keenmate/web-dropzone-core` (the headless engine) — the engine-only items are grouped under
their own headings.

This rc rebuilds the dropzone on `@keenmate/web-components-core` rc25 and the shared Keenmate
rules: one interaction model (`el.controller`, present-tense events with `on*` twins, one `ctx`
per callback), one cancel rule for uploads, every UI string in `labels` with page-wide
localization and a `locale`, icons through core `renderIcon`, render callbacks through core
`renderSlot`, and four satellites that are full core elements. It adds `readonly`, `required` (+ count rules as their own validity flags), responsive
rules, an armed drop target, an `action` event, screen-reader announcements and custom CSS the
core way. It is **breaking, with no aliases.** Note that a `^1.0.0-rc02` range **does** pull this
rc (npm matches later prereleases of the same `1.0.0`), so pin the version until the checklist
below is done.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/KeenMate/web-dropzone/blob/prod/CHANGELOG.md) (section
1.0.0-rc03); this document is the upgrade guide and the highlights.

## Breaking changes

### Attributes and properties renamed

The Keenmate components share one public vocabulary (booleans named `is*` / `should*` /
`has*`, counts named `*-count`); no aliases.

| rc02 | rc03 |
|---|---|
| `mode` / `el.mode` / type `DropzoneMode` | `render-mode` / `el.renderMode` / `DropzoneRenderMode` (`bulk` / `structural` / `headless`; now also settable as a property) |
| `max-visible-files` / `maxVisibleFiles` | `max-visible-file-count` / `maxVisibleFileCount` |
| `uploaded-deletable` / `el.uploadedDeletable` | `allow-uploaded-file-removal` / `el.isUploadedFileRemovalAllowed` |
| `reorder-completed` / `el.reorderCompleted` | `sink-completed` / `el.shouldSinkCompleted` |
| `reorder-completed-delay` / `reorderCompletedDelay` | `sink-completed-delay` / `sinkCompletedDelay` |
| `el.multiple` | `el.isMultiple` (attribute `multiple` unchanged) |
| `el.disabled` | `el.isDisabled` (attribute `disabled` — see [below](#disabled-is-a-presence-attribute)) |
| `el.showThumbnails` | `el.isThumbnailsShown` (attribute `show-thumbnails` unchanged) |
| `el.filesInside` | `el.isFilesInside` (attribute `files-inside` unchanged) |
| `el.autoUpload` | `el.shouldAutoUpload` (attribute `auto-upload` unchanged) |

### Text attributes are replaced by `labels`

Every UI string is one `labels` input (property or JSON attribute), merged per key over the
built-in English, with `{name}` / `{count}` / `{size}` placeholders. English defaults are
unchanged.

| rc02 | rc03 |
|---|---|
| `prompt-text` | `labels.prompt` (card text) — also `ariaLabels.prompt` for the icon-only minimal button |
| `hint-text` / `drag-active-text` / `no-file-chosen-text` / `overlay-text` | `labels.hint` / `labels.dragActive` / `labels.noFileChosen` / `labels.overlay` |
| `select-files-text` | `buttons.selectFiles` |
| `empty-message` | `messages.noData` (`''` = no empty-state element) |
| `summary-template` | `labels.summary` |
| `<web-dropzone-picker label hint no-file-chosen-text>` | the picker's own `labels` (`labels.prompt` / `buttons.selectFiles`, `labels.hint`, `labels.noFileChosen`) |
| `<web-dropzone-list empty-message>` | the list's own `labels` (`messages.noData`) |
| `<web-dropzone-indicator label>` | the indicator's own `labels` (`headers.indicator`, `messages.indicatorIdle`) |

```html
<!-- rc02 -->
<web-dropzone prompt-text="Přetáhněte soubory" empty-message="Žádné soubory"></web-dropzone>
<!-- rc03 -->
<web-dropzone labels='{"labels.prompt":"Přetáhněte soubory","messages.noData":"Žádné soubory"}'></web-dropzone>
```

A satellite's `labels` are merged over its store's. The full key list and the page-wide
dictionary are under [New features — localization](#new-features--localization).

### `value-format` is removed

`value-format` / `valueFormat` / the `ValueFormat` type are gone — nothing read them: files
always submit as `FormData` blobs under `name`. Drop the attribute; there is no replacement.

### `disabled` is a presence attribute

`disabled` (store and `<web-dropzone-picker>`) and the new `readonly` are native presence
booleans: any value, `disabled="false"` included, turns them on. Remove the attribute to enable.
The attribute reflects `el.isDisabled`.

### Stricter input values

The inputs (store and satellites) run on core's converters, so a value the dropzone can't use is
refused — a warning, the `input-rejected` event, the previous value kept — instead of being
accepted and misread.

| Input | rc02 | rc03 |
|---|---|---|
| `max-file-size`, `min-file-size`, `max-total-size` | an invalid size (`"lots"`, `"1.5b"`) fell back to `0` (unlimited) | refused; binary units incl. `KiB` / `MiB` accepted |
| `controls`, `item-controls` | unknown tokens dropped silently | the whole value refused |
| `max-file-count`, `min-file-count`, `max-visible-file-count`, `progress-throttle`, `sink-completed-delay` | negatives accepted | refused |
| `concurrency` | any integer | `< 1` refused |
| satellite enums (`position`, `list-appearance`, …) | an unknown value fell back to the default | refused |
| `el.labels = null` | — | refused; `el.labels = undefined` (or removing the attribute) restores English |

### Icon values follow the core icon order

`icon`, `overlay-icon` (and the new `cancel-icon` / `remove-icon`, the picker's `icon`) are drawn
by core `renderIcon`: markup (a value starting with `<`) is inserted raw → a core built-in name
(`check`, `close`, `delete`, `download`, …) is a glyph masked from `--base-icon-<name>` → the
element's `renderIconCallback(name, ctx)` → the page-wide `window.components.renderIconCallback`
→ an icon-font class list (`fa-solid fa-trash` → `<i class="dz__icon fa-solid fa-trash">`) →
anything else (an emoji) as escaped text.

| Value | rc02 | rc03 |
|---|---|---|
| `<svg …>` / `<img …>` | inserted as HTML | unchanged |
| an emoji (`📤`) | inserted as HTML | escaped text (looks the same) |
| a plain word (`upload`, `trash`) | inserted as HTML (showed the word) | a built-in name → glyph; otherwise an icon-font `<i class>` (invisible without that font) |
| `1 < 2` | inserted as HTML | escaped text |

The same order now applies to `fileIcons` values and `getFileIconCallback` results (new in this
release).

### Store access is `el.controller`

| rc02 | rc03 |
|---|---|
| `el.getStore()` → the internal `WebDropzone` (`DropzoneStoreAPI`) | `el.controller` — a `DropzoneController` facade built once, delegating to the live store (survives a rebuild); frozen; `controller.isReady` tells whether the store is built |
| satellite `getStore()` | satellite `controller` (the bound store's controller, `null` until bound) |
| `getFile(id)` → `FileState \| undefined` | `getFileById(id)` → `FileState \| null` (element, controller, engine) |
| `controller.getConfig()` | `controller.getOptions()` |
| `StatusSurfaceArgs.store` | `StatusSurfaceArgs.controller` (+ `element`) |

### Events are renamed and not composed

Events are present tense, bubble and are **not composed** (they no longer cross shadow roots — a
listener on the element or any light-DOM ancestor still gets them). Each has a camelCase `on*`
twin property that receives the same detail first (`el.onFileAdd = ({ file }) => …`). Every
detail carries `controller` and `element`, non-enumerable, so `JSON.stringify(detail)` sees only
the data.

| rc02 | rc03 | Detail |
|---|---|---|
| `file-added` | `file-add` | `{ file }` |
| `file-removed` | `file-remove` | `{ file }` |
| `files-changed` | `files-change` | `{ changedIds, files }` |
| `change` (no detail) | `change` | `{ files }` |
| `files-rejected` | `file-reject` | `{ rejectedFiles }` |
| `file-uploaded` | `file-upload` | `{ file }` |
| `file-deleted` | `file-delete` | `{ file }` — fires when the removed file had server state (upload completed or metadata stashed) |
| `file-status-changed` | `file-status-change` | `{ id, oldStatus, newStatus, file }` (was `prevStatus` / `nextStatus`) |
| `file-updated` | `file-update` | `{ file }` |
| `store-ready` (every build) + `data-ready` attribute | `ready` — once, after the first build (+ `ready` attribute, `:state(ready)`, `whenReady()`) | context only |
| list `dz-summary-click` / `dz-queue-open` | `summary-activate` / `queue-open` (+ `onSummaryActivate` / `onQueueOpen`) | context of the bound store |
| `file-row-update` (composed) | `file-row-update` — bubbles on the row element, not composed | `{ file }` |
| `dz-config-changed` | internal, not public | — |

`file-retry`, `file-progress` and `overlay-enter` / `overlay-leave` keep their names and gain
`on*` twins. The FOUC guard is `web-dropzone:not([ready])`.

### Callbacks take one `ctx`

Every callback takes ONE `ctx` argument carrying `controller` and `element` (non-enumerable).

| rc02 | rc03 |
|---|---|
| `beforeFilesAddedCallback(files)` | `beforeFilesAddCallback({ files, existingFiles })` — `false` cancels (reported in `file-reject` with code **`rejected`**, was `cancelled`; message `errors.rejected` "File rejected"), a `File[]` replaces the batch (validated again — the documented replacement now works) |
| `beforeFilesRemovedCallback(files)` | `beforeFilesRemoveCallback({ files, allFiles })` — only `false` cancels (`undefined` used to cancel) |
| `validateCallback(file, existingFiles)` | `validateCallback({ file, existingFiles })` |
| `uploadFileCallback(file, onProgress, signal, context)` | `uploadFileCallback({ file, signal, setProgress, startBytes, startPercent, metadata, setMetadata, uploadMetadata })` |
| picker `uploadCallback` / `addFiles(files, { uploadCallback })` | `uploadFileCallback` (same ctx) |
| `renderFileItemCallback(file, { index, displayMode, isInPopover })` | `renderFileItemCallback({ file, fileIndex, displayMode, isInPopover })` |
| `renderListWrapperCallback(rowsHtml, files)` | `renderListWrapperCallback({ rowsHtml, files })` |
| `renderPromptCallback()` / `renderSummaryCallback(files)` | `renderPromptCallback(ctx)` / `renderSummaryCallback({ files })` |
| `renderRolling{Body,FileInfo,Progress}Callback(args)` — config only | same, `args.controller` replaces `args.store`; now `<web-dropzone>` inputs |
| indicator `render{Body,FileInfo,Progress}Callback(args)` | names unchanged; `args.controller` replaces `args.store` |
| `customStylesCallback()` | `getCustomStylesCallback(ctx)` (+ the `custom-styles` attribute) |
| `persistStateCallback(key, state)` / `loadStateCallback(key)` | `saveStateCallback({ key, state })` / `loadStateCallback({ key })` — see [Persisted state](#persisted-state-the-core-way) |

Structural-mode rows that relied on the auto-wired buttons rename `data-action="remove"` →
`data-dz-action="remove"` and `data-action="row-action"` → `data-dz-action="row-action"`
(`data-action` is reserved for core action items).

### Render callback results follow core `renderSlot`

Every content-returning `render*Callback` (`renderFileItemCallback`, `renderListWrapperCallback`,
`renderPromptCallback`, `renderSummaryCallback`, `renderRolling*Callback`, the indicator's
`render*Callback`) reads its result the core way: a **string** = HTML, a **Node** = mounted,
**`null` / `undefined`** = the built-in rendering, **`false`** = hidden. The return type is the
exported `RenderCallbackResult`.

| Callback returns | rc02 | rc03 |
|---|---|---|
| `renderFileItemCallback` → `null` / `undefined` | no row (inline list); threw in the popover | the built-in row — return `false` for none |
| `renderPromptCallback` / `renderListWrapperCallback` → `null` | threw / printed `null` | the built-in prompt / the plain rows |
| `renderSummaryCallback` → an element | serialized through `outerHTML` | mounted (listeners survive) |

### One cancel rule

`cancelFile(id)` returns `Promise<void>` (element + controller). Nothing running → `cancelled` at
once; a running handler → status **`cancelling`** (`FileStatus` gains it), its `signal` aborts and
the cancel waits up to `cancel-timeout` ms (default 2000) for the handler to settle. Settles in
time → `cancelled`; times out → `cancel-timeout-behavior` (`error` — retryable,
`file.error = 'cancel-timeout'` — or `remove`). Late results are ignored and the concurrency slot
frees either way. `removeFile` / `removeFiles` / `clear` cancel a running file first and resolve
after that.

The row buttons split: **⊘ Cancel** (uploading / paused / queued; the row stays `cancelled` with
Retry) and **✕ Remove** (always; a running upload is cancelled first). In rc02 ✕ on an uploading
row cancelled it and a second ✕ removed it. `OverallProgress` gains `pendingCount` /
`cancellingCount`.

### Lifecycle: ready once, final destroy, removal tears down

| | rc02 | rc03 |
|---|---|---|
| `ready` | `store-ready` on every store build | once, after the first build; `defer` + `release()` hold the first build |
| `el.destroy()` | destroyed the store; the element rebuilt on reconnect | final — aborts uploads, clears the form value, the element stays inert (`isDestroyed`) |
| Moving the element (re-parent / reorder) | destroyed and rebuilt the store — files lost, uploads aborted | keeps files, uploads and an open popover |
| Removing the element | aborted uploads at once | one frame later: every upload is cancelled by the cancel rule (`file-cancel` fires), then the store is destroyed; `keep-alive-when-removed` keeps it running |

### Registration and logging

- Every tag is defined by core `registerComponent()` in the package entry. Importing a single
  module (e.g. `web-component-picker`) no longer defines its tag — import the package.
- The `DROPZONE` log bundle was silenced at load; it now prints warnings by default and follows
  the page-wide `window.components.logging`. `window.components['web-dropzone'].logging.getCategories()`
  returns the bare names `['INIT', 'FILE', 'UI', 'INTERACTION']`.

### CSS: flat BEM classes, loader, overlay, RTL

| rc02 | rc03 |
|---|---|
| `.dz__<block>__<element>` (`.dz__file-item__name`, `.dz__popover__row`, `.dz__dropzone__input`, …) | `.dz__<block>-<element>` (`.dz__file-item-name`, `.dz__popover-row`, `.dz__dropzone-input`, …); modifiers keep `--` |
| `.dz__indicator__spinner` (WAAPI spinner) | `.dz__indicator-loader` (core `renderLoader`, `role="status"`) |
| `--dz-status-spin-duration`, keyframes `dz-status-spin` | `--dz-loader-duration` (+ `--dz-loader-icon` / `-rotate` / `-size` / `-inline-size`), `dz-loader-spin`; the row glyph is `<span class="dz__loader dz__loader--inline">` |
| drag overlay: a `<div class="dz__overlay">` on `<body>`, reachable by page CSS | a core layer with its own shadow root; style it with `--dz-overlay-*` or `custom-styles` |
| `src/css/rtl.css` (`:host([dir="rtl"])` rules) | removed — logical properties follow the inherited direction |

CSS inside the shadow DOM (`custom-styles`, render callbacks) renames the same way.

### Theming reads the base-css-variables 2.0 names

The fallbacks read the `@keenmate/base-css-variables` 2.0 names: `--base-primary-color[-hover|-active]`
(was `--base-accent-*`), `--base-primary-bg-subtle[-hover]`, `--base-on-primary-text-color`,
`--base-outline-width` / `--base-focused-outline` (were `-ring`), `--base-*-text-color` (was `-text`).
Motion uses the contract's four speeds: `--dz-transition-fast` is 0.1s (was 150ms) and
`--dz-transition-normal` 0.15s (was 200ms); the 150ms hovers read `--dz-transition-normal`, so a
page that slowed hovers through `--dz-transition-fast` sets `--dz-transition-normal` instead.
`--dz-disabled-opacity` is `var(--base-disabled-opacity, 0.65)` (was `0.5`, applied twice on the
card).

### Persisted state the core way

`persistStateCallback` → `saveStateCallback({ key, state })` (`state` is the whole
`DropzoneState`); `loadStateCallback({ key })`; `storage-key` keeps its name. Set both callbacks;
either one alone switches localStorage off. The default localStorage key is
`km-state:web-dropzone:<storage-key>` (was `dz-state:<storage-key>`) — popover sizes saved by rc02
are not carried over. The callbacks are typed with core's `LoadStateCallback<DropzoneState>` /
`SaveStateCallback<DropzoneState>` (re-exported).

### `min-file-count` is `rangeUnderflow`, `required` is `valueMissing`

`min-file-count` set `validity.valueMissing` — also for an empty dropzone. Now every rule has its own
flag (core `setValidityFlag`, so none clears another), like native constraints:

| Rule | rc02 | rc03 |
|---|---|---|
| `min-file-count="N"`, 1..N-1 files | `valueMissing` | `rangeUnderflow` (message `errors.minFileCount` unchanged) |
| `min-file-count="N"`, no file | `valueMissing` | valid — an empty value is `required`'s |
| no file + new `required` | — | `valueMissing` (`errors.required`, "Add a file.") |
| more than `max-file-count` (cap lowered after files were added) | valid | `rangeOverflow` (`errors.maxFileCount`) |

`<web-dropzone min-file-count="1">` → `<web-dropzone required>`; "two or more" is
`required min-file-count="2"`. Read-only / disabled dropzones are never invalid now (native: barred
from validation) — rc02 applied `min-file-count` while read-only.

### Engine and types renamed

For code that builds its own renderer on `@keenmate/web-dropzone-core` or imports the types.
One settings shape for every Keenmate engine: constructor → `setOptions(partial)` →
`getOptions()`. No aliases.

| rc02 | rc03 |
|---|---|
| `DropzoneCore` | `DropzoneEngine` (`engine.controller` is its facade) |
| `core.updateConfig(partial)` (returned `true`) | `engine.setOptions(partial)` (returns nothing) |
| `core.getConfig()` | `engine.getOptions()` |
| `DropzoneConfig` | `DropzoneEngineOptions`; keys `isMultipleEnabled` → `isMultiple`, `maxVisibleFiles` → `maxVisibleFileCount`, `mode` → `renderMode`, `isFilesInsideEnabled` → `isFilesInside`, `isShowThumbnailsEnabled` → `isThumbnailsShown`, `isAutoUploadEnabled` → `shouldAutoUpload`, `isUploadedFileDeletable` → `isUploadedFileRemovalAllowed`, `isReorderCompletedEnabled` / `reorderCompletedDelay` → `shouldSinkCompleted` / `sinkCompletedDelay`; the text keys (`promptText`, …) → `labels`; `valueFormat` removed |
| `DropzoneStoreAPI` | `DropzoneController` (+ `createDropzoneController(getTarget)`) |
| `FileAddedEventDetail`, `FileRemovedEventDetail`, `FilesRejectedEventDetail`, `FileUploadedEventDetail`, `FileDeletedEventDetail`, `FileStatusChangedEventDetail`, `FileUpdatedEventDetail`, `FilesChangedEventDetail`, `DropzoneEventDetail` | `FileAddEventDetail`, `FileRemoveEventDetail`, `FileRejectEventDetail`, `FileUploadEventDetail`, `FileDeleteEventDetail`, `FileStatusChangeEventDetail`, `FileUpdateEventDetail`, `FilesChangeEventDetail`, `DropzoneEventMap` |
| `STATUS_LABELS` / `ACTION_LABELS` | removed — `DEFAULT_LABELS` + `resolveLabel()` / `createLabelFn()` |
| `createDropzoneSpinner()` | removed — the CSS loader `<span class="dz__loader">` |
| `dispatchComposedEvent` | removed — events go through core `emit()` / `dispatch()` |
| `ValueFormat`, `DropzoneMode` | removed / `DropzoneRenderMode` |
| own `escapeHtml` | core's (`@keenmate/web-dropzone-core` re-export): escapes `& < > " '`, takes any value |
| `DropzoneCore` protected storage methods | gone — the engine takes a core state store (`DropzoneEngineHost.stateStore`) |

The element's own config type is the new `DropzoneElementConfig`.

## Behaviour changes

### Dark mode follows the page

The page signal (`data-theme`, `data-bs-theme`, `.dark` / `.light` on `<html>` / `<body>`) comes
from core as `data-context-theme` on the store and the satellites, instead of
`:host-context()` (no Firefox support). The `prefers-color-scheme` rule is gone: an unsignalled
page decides (to follow the OS, declare `html { color-scheme: light dark }`). Dark mode flips
`color-scheme` instead of redeclaring every `--dz-*` colour. A themed wrapper needs
`theme-source="closest"`.

### `disabled` turns off every control

Under `disabled` (own, or a disabled `<fieldset>`) the row buttons (pause / resume / retry,
cancel, remove), Show more / less, the rolling queue button, the popover and bulk actions and the
summary line do nothing and leave the tab order — in rc02 the row buttons kept removing /
cancelling files. Bound list / progress / indicator satellites follow their store. Calls from code
still work.

### Overlays: popover and drawer join core's overlay tree

The compact popover and the indicator drawer close on Escape (focus back to the trigger) and on
an outside click, and opening another Keenmate overlay closes them. On a phone (core's device
class: touch-primary, short side under the tablet line) both are full-screen sheets; the popover
sheet closes on the phone Back gesture. The edge drawer (`position="right|left|top|bottom"`) is
core's `.km-drawer`; the new `drawer-mode` picks `non-modal` (default — page usable) or `modal`
(backdrop, page inert, Tab trapped). Opening moves focus to the Close button. The drawer's
accessible name is its title "Uploads" (was "Upload queue").

### The compact popover opens 4px from its trigger

The gap is the page token `--base-dropdown-offset` (was a hard-coded 8px). To keep the old look:
`web-dropzone { --base-dropdown-offset: 8px; }`.

### File sizes follow the locale

`formatFileSize()` formats through core `formatNumber` with the resolved locale (`locale` input →
`window.components.locale` → the browser): `1,5 MB` on a Czech page or browser (rc02 always
`1.5 MB`). Progress percents follow the same locale.

### `multiple="false"` replace reports the replaced file

A new file in single mode used to replace the current one silently (its upload kept running, no
`file-remove`). The replaced file now leaves like a removal: the cancel rule for a running upload
(`file-cancel`), then `file-remove` (+ `file-delete`) and `change`. A single-mode batch keeps its
first file; the rest are rejected with code `count`.

### Smaller behaviour changes

- `retryFile` restarts from 0 like resume (it kept the old progress).
- File ids come from core `createId('file')` (were `file-<time>-<random>`); still opaque strings.
- The rolling list's outgoing row leaves when its own animation ends (core `animateOut`), at once
  with motion off (was a fixed 500 ms timer).
- `el.controller` is frozen: adding or overwriting properties on it no longer sticks (throws in
  strict mode).
- A scrolled file list keeps its position across a DOM move and when a file is added to
  `<web-dropzone-list>`.

## New features — uploads and the file list

### Cancel all, cancel gate and `file-cancel`

`cancelAll()` (element + controller) cancels every uploading / pending / paused file and resolves
when all finished; a **Cancel all** button joins Pause all in the progress strip.
`beforeFilesCancelCallback({ files, allFiles })` vetoes with `false` (asked once for a batch).
`file-cancel` reports how it ended: `{ file, result: 'cancelled' | 'timeout-error' |
'timeout-remove', uploadedBytes, metadata }` — `metadata` carries what the handler stashed via
`ctx.setMetadata` (e.g. a tus.io upload URL) for server-side cleanup.

### `removeFiles(ids)` and `hasActiveUploads`

`removeFiles(ids, { confirm })` is the pair of `addFiles` (the remove gate runs once per batch);
`removeFile` and `clear` wrap it. `hasActiveUploads` is `true` while any file is pending,
uploading, paused or cancelling — the signal an app checks before leaving the page (the README
shows a `beforeunload` listener, a graceful `await cancelAll(); destroy()` and a router guard).

### `readonly`

`readonly` / `el.isReadonly` (also on `<web-dropzone-picker>`): the user can't change the
selection (no add, no row Remove, no Clear all), the files stay visible and are submitted, uploads
keep running. The selectors stay focusable (`aria-disabled="true"`).

### `required`

`required` / `el.isRequired` (reflects): no file selected → `validity.valueMissing`, message
`errors.required` ("Add a file."), the form refuses to submit; `checkValidity()` / `reportValidity()`
report it, the browser's bubble points at the visible selector. The host gets `aria-required`
(through `ElementInternals`) and `:state(required)`; read-only / disabled are never missing (core
SPEC §6.6). See [min-file-count is rangeUnderflow](#min-file-count-is-rangeunderflow-required-is-valuemissing)
for the count rules.

### Armed drop target

Opt-in `highlight-on-page-drag`: while files are dragged anywhere over the page, every opted-in
dropzone / picker is armed — `armed` attribute, `:state(armed)`, `el.isArmed`, card colour
`--dz-dropzone-bg-armed`; the card under the pointer keeps the active look. One shared page
watcher (core `watchPageDrag`).

### `action` event and `beforeActionCallback`

Every built-in button is a core action item: `beforeActionCallback` (`false` cancels) → the
built-in → the `action` event (`onAction`), a notification after the fact. Row actions `remove` /
`cancel` / `pause` / `resume` / `retry`, bulk `pause-all` / `resume-all` / `cancel-all` /
`retry-all` / `clear` / `add-more`. Buttons of a bound list / progress fire it on `<web-dropzone>`.
Headless: `DropzoneEngine.activateAction(request)`.

### Screen-reader announcements

Through core `announce()`: files added (one message per drop), rejected files with the reason, a
finished upload batch, a removed file. Each message is a `labels` key (`ariaLabels.announce*`);
`''` silences it.

## New features — localization

### `labels` keys, page-wide dictionary, `translateCallback`

Keys are flat `<elementType>.<name>` — `buttons`, `tooltips`, `ariaLabels`, `headers`, `labels`,
`messages`, `errors` — covering every string: status words, row buttons, the popover limits line,
the progress strip, the indicator, the validation messages (`errors.maxFileSize`, …) and the form
validity message. Page-wide: one flat dictionary
`window.components.locale.labels = { 'web-dropzone.buttons.selectFiles': '…' }` (a satellite-only
entry uses its tag). `translateCallback({ component, key, template, params, locale })` on the
element is asked before the page-wide one; `null` = not mine. An `ariaLabels.*` / `tooltips.*`
nobody set follows a translated sibling of the same name. Assigning `window.components.locale`
re-renders live.

### `locale`

A BCP-47 `locale` input for the numbers the dropzone formats (file sizes, progress percents,
`{count}` in labels). Unset follows `window.components.locale`, else the browser; satellites follow
their store. The engine takes `DropzoneEngineOptions.locale`.

## New features — icons and rendering

### Icon hooks and file-type icons

`renderIconCallback(name, ctx)` on the element maps your own icon names (asked after markup and
the built-in names, before the page-wide hook; `ctx.file` on a row button). New `cancel-icon` /
`remove-icon`. `fileIcons` (keyed by extension or category) and `getFileIconCallback({ file })`
override the file-type icons; their values go through the same icon order. Changing the page-wide
`window.components.renderIconCallback` repaints the icons in place (files, scroll, focus and an
open popover kept).

### Loader hook

`renderLoadingCallback` (store property; `ctx.context = 'upload'`, may return a cleanup) draws the
indicator chip's upload loader, else the page-wide `window.components.renderLoadingCallback`, else
the default `.dz__loader`.

## New features — element platform

### Satellites are core elements

`<web-dropzone-picker>`, `-list`, `-indicator`, `-progress` get core's `ready` / `whenReady()`,
`defer` + `release()`, `destroy()`, `motion`, `theme-source`, `responsive`, `labels`,
`custom-styles` and a `window.components[tag]` entry. `for` is also `el.htmlFor` (changing it
re-binds). The picker gains `openFileDialog()`; `bindToStore(storeEl, owner?)` takes an owner
whose custom CSS applies too.

### Custom CSS the core way

`custom-styles` / `customStyles` next to `getCustomStylesCallback`, plus a page layer per tag
(`window.components['web-dropzone'].customStyles`). The store's CSS reaches the satellites it
mounts and the drag-overlay layer.

### Responsive rules

`responsive` (map or JSON attribute) and `responsiveCallback`, per tag and page-wide (core SPEC
§6.7): partial configs per device class (`device`) and window width (`breakpoint`); instance attributes win
over page rules. Types `DropzoneResponsiveMap` / `DropzoneResponsiveCallback`.

### Typed properties and a Custom Elements Manifest

Every element class has typed properties (`DropzoneElementConfig`, `DropzonePickerElementConfig`,
`DropzoneListElementConfig`, `DropzoneIndicatorElementConfig`, `SatelliteElementConfig`), and the
package ships `custom-elements.json`, `web-types.json` and VS Code data for the five tags.
