RC01 · Why headless mode unlocks React patterns

React expects to own the DOM it manages. With render-mode="headless" the dropzone steps back: it holds FileState[], dispatches events, and lets your component own the rendering. The native <web-dropzone-picker> satellite is still used as the drop surface, because re-implementing drag-and-drop in React would mean re-implementing a feature web-dropzone already ships.

Pattern
  • One useRef on the store element, one useEffect attaches the listener + upload callback.
  • useState holds the file array; the files-change handler replaces it whole (the event is rAF-coalesced so this is cheap).
  • Per-row actions call store.pauseFile(id) / resumeFile / retryFile — the next event tick re-renders.

This demo uses htm for tagged-template JSX so the page works without a build step. With Babel or a real bundler you'd write the same code in regular JSX.

Heads-up: htm passes attribute names through verbatim, so you still write className (not class) and onClick (not onclick) — anything React expects. class is silently dropped by React, which means CSS classes vanish and styled elements like the progress bar end up invisible.

CSS transitions on the progress bar: avoid transition: width Xms on the bar fill. files-change fires ≈ 60 Hz during an upload, so a 180 ms transition makes the bar lag the numeric % by ~11 frames — looks like the bar is barely moving while the text shoots ahead. Drive the width directly from a CSS custom property on the row and skip the transition; React's per-event commits already give you smooth motion.
