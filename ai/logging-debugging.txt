LOGGING & DEBUGGING
===================

LOGGERS
-------
Built on @keenmate/web-components-core /logging (createLoggers; vendored
loglevel engine). Namespace DROPZONE, four categories:

  DROPZONE:INIT         element / store lifecycle, config
  DROPZONE:FILE         add / remove, validation, progress, status, auto-retry,
                        cancel timeouts
  DROPZONE:UI           rendering, popover, overlay, persistence fallbacks
  DROPZONE:INTERACTION  user interaction

The dropzone bundle is SILENT by default (disabled on load).

CONSOLE CONTROL (GLOBAL API)
----------------------------
const log = window.components['web-dropzone'].logging;

log.enableLogging();                              // every category at debug
log.disableLogging();                             // silent
log.setLogLevel('warn');                          // all categories
log.setCategoryLevel('DROPZONE:FILE', 'debug');   // one category
log.setCategoryLevel('FILE', 'debug');            // bare name also accepted
log.getCategories();                              // ['DROPZONE:INIT', ...]

Levels: 'trace' | 'debug' | 'info' | 'warn' | 'error' | 'silent'.

CODE CONTROL
------------
import {
  enableLogging, disableLogging, setLogLevel, setCategoryLevel,
  LOGGING_CATEGORIES, initLogger, fileLogger, uiLogger, interactionLogger
} from '@keenmate/web-dropzone';

if (import.meta.env.DEV) setCategoryLevel('DROPZONE:FILE', 'debug');

The loggers are loglevel-style: .trace/.debug/.info/.warn/.error.

CORE MESSAGES
-------------
Messages from web-components-core about the element (invalid attribute values,
before*Callback throws, twin errors) go to core's CORE bundle (dropzone does
not register a per-tag bundle with core), which defaults to 'warn' - so they
show up even while DROPZONE logging is off. Watch the console when authoring
markup.

Page-wide switch (core, non-enumerable): applies to EVERY bundle on the page,
CORE and DROPZONE included:

window.components.logging.disableLogging();     // everything silent
window.components.logging.enableLogging('debug');
window.components.logging.setLogLevel('warn');
window.components.logging.getCategories();      // ['CORE:ELEMENT', 'DROPZONE:INIT', ...]

A later window.components['web-dropzone'].logging.* call wins for dropzone.

Typical core warnings:
  invalid attribute value (e.g. max-file-size="lots", labels='not json')
    -> warned, previous value kept
  a before*Callback threw -> logged, treated as a veto

USEFUL DEBUG OUTPUT
-------------------
DROPZONE:FILE debug shows the upload pipeline step by step:
  'Files added' / 'Files rejected' (warn) / 'Files removed'
  'File progress updated', 'File status updated'
  'Auto-retry: handler rejected' / 'scheduling the next attempt' /
  'snapping progress back to the baseline (optimistic mode)' /
  'giving up - attempts exhausted' / 'stopped during the delay'
  'Cancel timed out - the upload handler ignored its AbortSignal' (warn)

INSPECTING STATE
----------------
const dz = document.querySelector('web-dropzone');

dz.files                                   // FileState[]
dz.controller.getConfig()                  // merged config (defaults + inputs)
dz.controller.getOverallProgress()         // counts + percent
dz.controller.isReady                      // store built?
window.components['web-dropzone'].getInstances()
window.components['web-dropzone'].version()
window.components['web-dropzone'].config.core   // { name, version } of web-dropzone-core

Event tracing:
['file-add','file-remove','change','file-reject','file-status-change',
 'file-cancel','file-delete','file-upload','ready']
  .forEach(n => dz.addEventListener(n, e => console.log(n, e.detail)));
(console.log of e.detail does not show controller / element - they are
non-enumerable; access them directly.)

TROUBLESHOOTING
---------------
Nothing renders
  -> no display attribute and no render-mode: inferred headless. Add
     display-mode="list" (or render-mode="bulk").

Render callbacks ignored
  -> they need render-mode="structural" explicitly.

Property set but not applied when read back
  -> writes coalesce on a microtask: await dz.whenSettled(), or use
     dz.setAttributes({...}) / dz.batch(fn). Element methods flush first.

Files rejected unexpectedly
  -> listen to file-reject and log validation.code; dedupe-mode="name" rejects
     same-named files; max-file-count counts files already in the list.

Satellite shows nothing / "store not found" warning
  -> for= must be the id of a <web-dropzone> reachable by
     document.getElementById; inside a shadow root use bindToStore(el).

Event listener on an outer element never fires
  -> events are NOT composed: they don't leave an enclosing shadow root.
     Listen on the dropzone itself.

Cancel stuck on "Cancelling..." then error 'cancel-timeout'
  -> the upload handler ignored ctx.signal. Pass signal to fetch / abort the
     XHR. Tune cancel-timeout / cancel-timeout-behavior.

Uploads stopped after removing the element
  -> removal cancels uploads and destroys the store by design; use
     keep-alive-when-removed for detach/reattach flows.

All files vanished after changing display attributes
  -> the change flipped the resolved mode (e.g. headless -> bulk); a mode flip
     rebuilds the store and removes files (reported via file-remove / change).
     Set render-mode explicitly to avoid accidental flips.

--dz-* set on <web-dropzone> not reaching a standalone satellite
  -> standalone satellites carry their own defaults; set the variables on the
     satellite or a common ancestor.

Form submits no files
  -> needs `name`, ElementInternals support, and
     enctype="multipart/form-data" for native submission.

Pause / Resume / Cancel all buttons missing in the progress strip
  -> they need a store-level uploadFileCallback (per-picker handlers alone
     don't enable them).
