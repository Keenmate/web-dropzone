FORM INTEGRATION
================

<web-dropzone> is a form-associated custom element (static formAssociated =
true; ElementInternals owned by web-components-core). With a `name` it
submits the selected files as REAL File blobs - like <input type="file">.

BASIC FORM
----------
<form action="/upload" method="post" enctype="multipart/form-data">
  <input name="title">
  <web-dropzone name="attachments" display-mode="list" max-file-count="3"></web-dropzone>
  <button type="submit">Send</button>
</form>

Submits: title=..., attachments=<file 1>, attachments=<file 2>, ...
(one FormData entry per file, under `name`, with the file's name as filename).
Use enctype="multipart/form-data" for native submission, as with any file input.

HOW IT WORKS
------------
- On every selection change (add / remove / clear) the element calls
  internals.setFormValue(FormData) with every selected File under `name`
  BEFORE the `change` event listeners run - a change handler reading
  new FormData(form) sees the new selection.
- No name, or no files -> setFormValue(null) (nothing submitted).
- Changing `name` re-stamps the value.
- No hidden <input> elements are created.
- Without ElementInternals (old browsers, jsdom) this is a no-op; read
  dz.files yourself.

SUBMIT WITH fetch
-----------------
form.addEventListener('submit', async (e) => {
  e.preventDefault();
  const body = new FormData(form);          // already contains the File blobs
  await fetch(form.action, { method: 'POST', body });
});

Or build it yourself:
const body = new FormData();
for (const f of dz.files) body.append('files[]', f.file, f.name);

value-format
------------
value-format="json" | "csv" | "array" (default json) is accepted and reflected
but currently has NO effect: files always submit as blobs. It is kept for a
possible future text serialization. (Older versions wrote hidden inputs with
file names; that mechanism was removed.)

REQUIRED / MINIMUM FILES
------------------------
<web-dropzone name="docs" min-file-count="2" display-mode="list"></web-dropzone>

While fewer than min-file-count files are selected, validity is
{ valueMissing: true } with the message "At least 2 files required"
("At least 1 file required" for 1). Native submit is blocked and the
browser shows the message; form.checkValidity() / reportValidity() report it.
min-file-count never rejects files on add.

There is no `required` attribute - use min-file-count="1".

RESET
-----
form.reset() calls formResetCallback -> the selection is cleared
(like clear() without the confirm gate: running uploads are cancelled first,
file-remove / change fire).

DISABLED FIELDSET
-----------------
<fieldset disabled> ... <web-dropzone name="f" display-mode="list"></web-dropzone> </fieldset>

An ancestor disabled fieldset disables the dropzone (no clicks / drops);
re-enabling the fieldset restores it. dz.isDisabled keeps reporting the element's
own `disabled` value (like a native input). `disabled` is a reflected boolean
attribute: dz.isDisabled = false removes it.

READONLY
--------
<web-dropzone readonly name="docs">: the user can't change the selection (no
add via click / drop / overlay / Add more, no row Remove, no Clear all), but the
files stay visible and ARE submitted with the form. Uploads keep running; the
programmatic API still works. dz.isReadonly (reflected). Unlike disabled, the
selector controls stay focusable (aria-disabled="true") - they just never open
the file dialog.

el.form
-------
dz.form returns the owning <form> (core). Frameworks that delegate by
target.form (e.g. Phoenix LiveView phx-change) resolve the form correctly.
Note: `change` is NOT composed but bubbles - a listener on the form receives
it when <web-dropzone> sits in the form's light DOM.

UPLOAD FIRST, SUBMIT IDS
------------------------
Common pattern: upload with uploadFileCallback, then submit server ids
instead of blobs. Don't give the dropzone a `name` (or remove it) and add
your own hidden input:

<form id="f">
  <web-dropzone id="dz" display-mode="detailed"></web-dropzone>
  <input type="hidden" name="fileIds">
</form>

dz.uploadFileCallback = async ({ file, signal }) => {
  const res = await fetch('/api/files', { method: 'POST', body: file, signal });
  return { metadata: { serverId: (await res.json()).id } };
};
dz.onChange = sync; dz.onFileUpload = sync;
function sync({ controller }) {
  f.fileIds.value = JSON.stringify(controller.getFiles()
    .filter(x => x.status === 'complete').map(x => x.metadata.serverId));
}

Block submit until uploads are done:
f.addEventListener('submit', (e) => {
  const p = dz.controller.getOverallProgress();
  if (p.uploadingCount + p.pendingCount + p.pausedCount > 0) {
    e.preventDefault();
    alert('Uploads still running');
  }
});

STAGE AND SUBMIT TOGETHER
-------------------------
<web-dropzone id="dz" auto-upload="false" display-mode="detailed"></web-dropzone>
<button id="send">Upload & save</button>

send.onclick = async () => {
  await dz.uploadAll();
  if (dz.files.some(f => f.status !== 'complete')) return alert('Some uploads failed');
  form.requestSubmit();
};

DRAG OVERLAY ON A FORM
----------------------
<form id="mail">
  ...
  <web-dropzone name="attachments" display-mode="compact" overlay-target="mail"></web-dropzone>
</form>
Dropping files anywhere over the form adds them. See display-modes.txt.

SATELLITES AND FORMS
--------------------
Only <web-dropzone> (the store) is form-associated. Place the store inside the
<form> (it may be headless/invisible) and put pickers / lists anywhere:

<form>
  <web-dropzone id="s" name="files"></web-dropzone>       <!-- headless store -->
  <web-dropzone-picker for="s"></web-dropzone-picker>
</form>
<web-dropzone-list for="s"></web-dropzone-list>

FRAMEWORK FORMS
---------------
React / Vue form libraries: treat the dropzone as uncontrolled. Mirror
dz.files (or ids) into form state from `change` / `files-change`, and set
values back only via addFiles / removeFiles / clear.
