STYLING & THEMING
=================

All styling is Shadow DOM + CSS custom properties (--dz-*). Set them on
<web-dropzone> (or any ancestor, or :root). They inherit into the internal
satellites the bulk mode mounts.

QUICK THEME
-----------
web-dropzone {
  --dz-accent-color: #10b981;
  --dz-dropzone-border-radius: 1rem;
  --dz-dropzone-border: 2px dashed #a7f3d0;
}

SIZING: --dz-rem
----------------
Every size is calc(N * var(--dz-rem, 10px)). Scale a whole instance:

<web-dropzone style="--dz-rem: 8px"  display-mode="list"></web-dropzone>   <!-- 80% -->
<web-dropzone style="--dz-rem: 12px" display-mode="list"></web-dropzone>   <!-- 120% -->

Pure Admin: --dz-rem: 1rem (with html { font-size: 10px }).
--dz-rem and --dz-file-list-max-height are intentionally NOT declared at
:host, so a value on a parent reaches every satellite.

TWO-LAYER VARIABLES (--base-* -> --dz-*)
----------------------------------------
--dz-* tokens read @keenmate/base-css-variables (the --base-* contract) with fallbacks.
Without the contract the fallbacks give the same colors: inputs fall back to the
contract defaults, derived tokens to the contract's formula on the --dz-* input
(so --dz-accent-color alone re-colors hover, tint and text on the accent).

--dz-accent-color         var(--base-primary-color,        #3b82f6)
--dz-accent-color-hover   var(--base-primary-color-hover,  ...)
--dz-accent-color-active  var(--base-primary-color-active, ...)
--dz-accent-color-light   var(--base-primary-bg-subtle, ...)
--dz-text-color-1/2/3     var(--base-text-color-1/2/3, ...)
--dz-text-on-accent       var(--base-on-primary-text-color, <black or white by APCA>)
--dz-main-bg              var(--base-main-bg, light-dark(#ffffff, #1e293b))
--dz-background           var(--dz-main-bg)
--dz-primary-bg           var(--base-elevated-bg, ...)
--dz-primary-bg-hover     var(--base-hover-bg, ...)
--dz-border-color         var(--base-border-color, ...)
--dz-success-color        var(--base-success-color, ...)
--dz-error-color          var(--base-danger-color, ...)
--dz-warning-color        var(--base-warning-color, ...)
Font sizes / radii read --base-font-size-xs/sm/base, --base-border-radius-sm/md/lg,
--base-font-weight-*, --base-line-height-normal; shadows read --dz-shadow-color (-> --base-shadow-color).
Font: --dz-font-family (falls back to --base-font-family, then inherit).

So a page theme (Theme Designer / pure-admin) themes the dropzone with no
--dz-* overrides. The full list of consumed --base-* and exposed --dz-* is in
@keenmate/web-dropzone/manifest (component-variables.manifest.json).

DARK MODE
---------
Colors use light-dark(), so the component follows `color-scheme`:
- Page signal (data-theme / data-bs-theme / .dark / .light on <html> or <body>)
  is mirrored by web-components-core onto the host as data-context-theme, which
  flips color-scheme. A themed wrapper elsewhere needs theme-source="closest".
- No page signal: the host inherits the page's color-scheme. There is NO
  prefers-color-scheme rule - to follow the OS declare
  html { color-scheme: light dark; }
- Per instance: <web-dropzone data-theme="dark"> or data-theme="light".
Dark mode only flips color-scheme; it does not overwrite your --base-* values.

surface tokens (--dz-surface-color, --dz-accent-color, --dz-*-bg, ...) and
--base-shadow-color.

EXAMPLES
--------
/* Scrollable list */
web-dropzone { --dz-file-list-max-height: 30rem; }

/* Fit thumbnails instead of cropping, denser grid */
web-dropzone {
  --dz-preview-item-object-fit: contain;
  --dz-preview-grid-columns: repeat(auto-fill, minmax(8rem, 1fr));
  --dz-preview-grid-gap: 0.5rem;
}

/* Non-resizable, wider popover */
web-dropzone { --dz-popover-resize: none; --dz-popover-width: 60rem; }

/* Hide the icon slot in badges */
web-dropzone { --dz-badge-icon-size: 0; }

/* Corporate red */
web-dropzone {
  --dz-accent-color: #c8102e;
  --dz-accent-color-hover: #a50d26;
  --dz-text-on-accent: #fff;
  --dz-dropzone-bg-active: color-mix(in srgb, #c8102e 6%, transparent);
}

SATELLITES & THE `managed` ATTRIBUTE
------------------------------------
The token defaults are declared on :host(:not([managed])). Satellites that
bulk-mode <web-dropzone> mounts internally carry `managed`, so they declare
nothing and inherit every --dz-* from the store host. Standalone satellites
(<web-dropzone-list for="...">) are not managed: they carry their own
defaults - theme them directly (or via an ancestor / :root, which still works
for tokens you set yourself).

SHADOW PARTS & HOST ATTRIBUTES
------------------------------
<web-dropzone-indicator>  ::part(chip), ::part(drawer)
                          [data-position], [data-drawer], [data-drawer-open]
<web-dropzone-progress>   ::part(root); [data-status="uploading|paused|error|complete"],
                          [data-empty="true"] when idle
<web-dropzone>            [ready] + :state(ready) after the first build (FOUC guard)

web-dropzone-indicator::part(chip) { border: 0; background: none; padding: 0; }
web-dropzone:not([ready]) { visibility: hidden; }

CASCADE LAYERS
--------------
Inside each shadow root: @layer variables, component, overrides.
- Unlayered rules beat all layers (only relevant to CSS injected into the
  shadow root, e.g. via getCustomStylesCallback).
- A global universal reset in the page doesn't pierce Shadow DOM, but
  inherited properties still flow in.

INJECTING CSS
-------------
dz.getCustomStylesCallback = () => `
  .dz__file-item__name { font-family: 'JetBrains Mono', monospace; }
`;
Prepended <style> in <web-dropzone>'s shadow root (so @import/@font-face
work). Bulk-mode satellites have their own shadow roots and do NOT receive it -
use variables, or structural mode for in-element rows. Class names (.dz__*)
are internal markup, not a versioned API.
