CUSTOM RENDERING
================

Three levels of customization, from least to most work:
1. bulk mode + CSS variables / ::part        (styling-theming.txt)
2. structural mode + render callbacks        (this file)
3. headless mode + your own DOM / satellites (advanced-patterns.txt, satellites.txt)

Plus mode-independent hooks: file icons (fileIcons / getFileIconCallback),
row button glyphs (cancel-icon / remove-icon), prompt icon (icon),
overlay icon (overlay-icon), and custom-styles / getCustomStylesCallback.

STRUCTURAL MODE IS REQUIRED
---------------------------
Render callbacks are honored ONLY with an explicit render-mode="structural".
In bulk mode they are ignored even if set; mode is never inferred as structural.

<web-dropzone id="dz" render-mode="structural" display-mode="detailed"></web-dropzone>

Every callback takes ONE ctx object. ctx also carries `controller`
(DropzoneController) and `element` (the <web-dropzone>), non-enumerable -
destructure them when needed.

CALLBACK OVERVIEW
-----------------
renderFileItemCallback({ file, fileIndex, displayMode, isInPopover })  -> string | HTMLElement
renderListWrapperCallback({ rowsHtml, files })                      -> string | HTMLElement
renderPromptCallback(ctx)                                           -> string | HTMLElement
renderSummaryCallback({ files })                                    -> string | HTMLElement
renderRollingBodyCallback(args)        StatusSurfaceArgs -> string | HTMLElement | false | null
renderRollingFileInfoCallback(args)    (rolling list appearance only)
renderRollingProgressCallback(args)

All are property-only (no attribute). Return values are inserted as HTML and
are NOT sanitized - escape file names yourself.

CUSTOM FILE ROW (STRING)
------------------------
const esc = (s) => s.replace(/[&<>"']/g, c => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c]));

dz.renderFileItemCallback = ({ file }) => `
  <div class="receipt-row" data-file-id="${file.id}">
    <span class="name">${esc(file.name)}</span>
    <span class="size">${(file.size / 1024).toFixed(1)} KB</span>
    <span class="status">${file.status} ${Math.round(file.progress)}%</span>
    <button data-dz-action="cancel" data-file-id="${file.id}">Cancel</button>
    <button data-dz-action="remove" data-file-id="${file.id}">&times;</button>
  </div>`;

Required hooks:
- data-file-id="${file.id}" on the row root, so the component can find and
  replace the row on state changes.
- Built-in actions are auto-wired by attribute (needs data-file-id too):
    data-dz-action="remove"      Remove (runs beforeFilesRemoveCallback)
    data-dz-action="cancel"      Cancel (runs beforeFilesCancelCallback)
    data-dz-action="row-action"  pause / resume / retry, chosen by status
- String rows are re-rendered (replaceWith) on every status/progress change,
  so listeners added by hand are lost each tick; use data-dz-action or the
  element-return model below. Consider progress-throttle="120".

NOTE: data-action (without "dz") is reserved for core action items and is not
auto-wired here.

CUSTOM FILE ROW (ELEMENT, EVENT-DRIVEN)
---------------------------------------
Return an HTMLElement and the component keeps it across state changes,
dispatching `file-row-update` on it instead of re-rendering. Listeners you
attach survive pause / resume / retry / reorder.

dz.renderFileItemCallback = ({ file }) => {
  const row = document.createElement('div');
  row.dataset.fileId = file.id;
  row.innerHTML = `
    <span class="star">&#9734;</span>
    <span class="name"></span>
    <progress max="100" value="0"></progress>
    <span class="pct">0%</span>`;
  row.querySelector('.name').textContent = file.name;
  row.querySelector('.star').addEventListener('click', (e) => {
    e.currentTarget.classList.toggle('on');
  });
  row.addEventListener('file-row-update', (e) => {
    const { file } = e.detail;               // fresh FileState (+ controller, element)
    row.querySelector('progress').value = file.progress;
    row.querySelector('.pct').textContent = Math.round(file.progress) + '%';
  });
  return row;
};

file-row-update bubbles, is not composed, and is dispatched on the row element
(inside the shadow root) - listen on the row itself.

Caveat: if renderListWrapperCallback is also set, rows go through the string
path (outerHTML) and element identity is NOT preserved.

LIST WRAPPER (TABLES)
---------------------
dz.renderListWrapperCallback = ({ rowsHtml, files }) => `
  <table class="files">
    <thead><tr><th>Name</th><th>Size</th><th></th></tr></thead>
    <tbody>${rowsHtml}</tbody>
  </table>`;

dz.renderFileItemCallback = ({ file }) => `
  <tr data-file-id="${file.id}">
    <td>${esc(file.name)}</td><td>${file.size}</td>
    <td><button data-dz-action="remove" data-file-id="${file.id}">&times;</button></td>
  </tr>`;

Bare <tr>/<td>/<th>/<tbody>/<thead>/<tfoot> fragments are parsed in a table
context, so row callbacks may return table rows directly.

PROMPT AND SUMMARY
------------------
dz.renderPromptCallback = ({ controller }) => `
  <div class="my-prompt">Drop invoices (${controller.getFiles().length} so far)</div>`;

dz.renderSummaryCallback = ({ files }) => `
  <div class="dz__summary-line" tabindex="0" role="button">
    ${files.length} attachment(s)
  </div>`;

renderSummaryCallback (compact / popover): keep an element with class
dz__summary-line - the popover's click/keyboard handler binds to it.

ROLLING LIST PARTS
------------------
Same contract as <web-dropzone-indicator>'s render callbacks
(StatusSurfaceArgs, see satellites.txt):

dz.renderRollingProgressCallback = ({ currentFile, overallPercent, aggregate }) =>
  currentFile
    ? `${Math.round(currentFile.progress)}% - ${aggregate.complete}/${aggregate.total} done`
    : null;                                   // null -> library default

dz.renderRollingBodyCallback = ({ aggregate }) =>
  aggregate.total === 0 ? false : null;       // false hides the rolling block

Return rules: null/undefined = default part; false = hide; string = innerHTML
(skipped if identical to the previous string); HTMLElement = mounted (skipped if
it is already the slot's only child - cache elements/loaders outside the
callback to keep animations running). For a loader in a custom part use the
shared CSS loader: <span class="dz__loader"> (--dz-loader-* tokens).

FILE ICONS (ANY MODE)
---------------------
Each row's icon comes from the file's category: image, video, audio, pdf, doc,
spreadsheet, archive, code, text, default (Lucide SVGs).

dz.fileIcons = {
  psd: '<svg viewBox="0 0 24 24">...</svg>',   // by extension (dot optional, case-insensitive)
  '.fig': '<img src="/icons/figma.svg" alt="">',
  archive: '&#128230;'                          // whole category
};

dz.getFileIconCallback = ({ file }) =>
  file.name.endsWith('.sketch') ? '<svg>...</svg>' : null;   // null -> fall through

Resolution order: getFileIconCallback -> fileIcons[extension] ->
fileIcons[category] -> built-in category icon. Both are property-only,
raw HTML, NOT sanitized. FILE_TYPE_ICONS / UI_ICONS export the built-ins.

OTHER RAW-HTML INPUTS
---------------------
icon           prompt icon (card / minimal)       default UI_ICONS.cloudUpload
overlay-icon   drag overlay icon                  default UI_ICONS.upload
cancel-icon    row Cancel button glyph            default CANCEL_ICON
remove-icon    row Remove button glyph            default CSS-masked x (--dz-icon-remove)

XSS: icon, overlay-icon, cancel-icon, remove-icon, fileIcons,
getFileIconCallback and every render*Callback are inserted via innerHTML
without sanitizing. Sanitize anything user-derived (e.g. DOMPurify).

CUSTOM STYLES INTO THE SHADOW ROOT
----------------------------------
<web-dropzone render-mode="structural" custom-styles=".dz__file-item { border-style: dotted; }"></web-dropzone>

dz.customStyles = '.dz__file-item { border-style: dotted; }';   // same, as a property
dz.getCustomStylesCallback = () => `
  @import url('https://fonts.example.com/inter.css');
  .dz__file-item-name { font-weight: 600; }
`;

- Core createCustomStyles(): the page layer
  window.components['web-dropzone'].customStyles / .getCustomStylesCallback(ctx)
  first, then the instance's (custom-styles attribute / customStyles property,
  or getCustomStylesCallback, which wins over customStyles) - so an instance
  overrides the page rules. Both are live; re-assigning replaces.
- Callback: called with ctx (controller / element); return a CSS string or null.
- Raw CSS, NOT sanitized. An @import (icon font) is also linked once in the
  document <head> (Chromium ignores @font-face inside a shadow root).
- Applies to <web-dropzone>'s own shadow root only. In bulk mode the picker /
  list / progress are satellite elements with their OWN shadow roots, so its
  rules won't reach them - use the per-tag page layer
  (window.components['web-dropzone-picker'].customStyles, ...-list, ...-progress),
  --dz-* variables (they inherit into managed satellites), or structural mode.
  Standalone satellites take their own custom-styles / getCustomStylesCallback.
- Class names are flat BEM (.dz__file-item-name, not .dz__file-item__name).

LIMITS OF STRUCTURAL MODE
-------------------------
- Structural mode uses the in-element renderer, not the satellite elements.
- There is no render callback for the progress strip or the popover table:
  popover rows always use the built-in compact row, so in practice
  renderFileItemCallback is only called with isInPopover === false.
  Use CSS variables or go headless.
- Popover header/footer text ("Add more", "Clear all", limits line) is not
  replaceable.
