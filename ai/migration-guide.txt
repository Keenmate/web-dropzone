MIGRATION GUIDE
===============

Migrating between @keenmate/web-dropzone versions. Newest first.
Release line: pre-rc builds -> 1.0.0-rc01 (2026-08-05) -> 1.0.0-rc02
(2026-08-14) -> 1.0.0-rc03 (current [Unreleased] in CHANGELOG).

No stable 1.0.0 exists, so `^1.0.0-rc02` ranges WILL pull rc03 - pin
until you have migrated.

=====================================================================
1.0.0-rc02 -> 1.0.0-rc03   (BREAKING)
=====================================================================

STEP 1: VERB GLOSSARY RENAMES
-----------------------------
cancel = stop a running op, abort = only the AbortSignal, remove = local list
removal, delete = server-side, clear = empty a set, destroy = the only
teardown verb.

| Old                                                   | New                                   |
|-------------------------------------------------------|---------------------------------------|
| reorder-completed / isReorderCompletedEnabled /       | sink-completed /               |
|   el.reorderCompleted                                 |   shouldSinkCompleted                 |
| file-reject code 'cancelled' (add gate veto)         | 'rejected'                            |

STEP 2: STORE ACCESS
--------------------
| Old                                         | New                                         |
|---------------------------------------------|---------------------------------------------|
| el.getStore() (internal WebDropzone)        | el.controller (DropzoneController facade;   |
|                                             |   survives rebuilds; .isReady)              |
| DropzoneStoreAPI type                       | DropzoneController (+ createDropzoneController) |
| DropzoneCore class                          | DropzoneEngine (engine.controller)          |
| satellite.getStore()                        | satellite.controller (null until bound)     |
| StatusSurfaceArgs.store                     | StatusSurfaceArgs.controller (+ element)    |
| dispatchComposedEvent export                | removed                                     |

STEP 3: EVENTS (renamed, NOT composed anymore, on* twins)
---------------------------------------------------------
Events now bubble but do NOT cross shadow roots. A listener on the element or
a light-DOM ancestor still works; a listener outside an enclosing shadow root
must move onto the element.

| Old                         | New                                  | Detail                         |
|-----------------------------|--------------------------------------|--------------------------------|
| file-added                  | file-add / onFileAdd                 | { file }                       |
| file-removed                | file-remove / onFileRemove           | { file }                       |
| files-changed               | files-change / onFilesChange         | { changedIds, files }          |
| change (no detail)          | change / onChange                    | { files }                      |
| files-rejected              | file-reject / onFileReject         | { rejectedFiles }              |
| file-retry                  | file-retry / onFileRetry             | { file }                       |
| file-uploaded               | file-upload / onFileUpload | { file }                |
| file-deleted                | file-delete / onFileDelete           | { file }                       |
| file-progress               | file-progress / onFileProgress       | { id, progress, status, file } |
| file-status-changed         | file-status-change / onFileStatusChange | { id, oldStatus, newStatus, file } |
| file-updated                | file-update / onFileUpdate           | { file }                       |
| overlay-enter / -leave      | same + onOverlayEnter / onOverlayLeave | { overlayElement }           |
| store-ready                 | ready / onReady (core, ONCE)         | context only                   |
| list dz-summary-click       | summary-activate                     | store context                  |
| list dz-queue-open          | queue-open                           | store context                  |
| file-row-update (composed)  | file-row-update on the row, not composed | { file } + context         |
| dz-config-changed           | internal, not public                 | -                              |
(new) file-cancel / onFileCancel: { file, result, uploadedBytes, metadata }

Every detail carries non-enumerable controller + element.

STEP 4: CALLBACKS TAKE ONE ctx
------------------------------
| Old                                                    | New                                           |
|--------------------------------------------------------|-----------------------------------------------|
| beforeFilesAddedCallback(files, existingFiles) -> bool | beforeFilesAddCallback({ files, existingFiles }) |
|                                                        |   false vetoes (code 'rejected'); File[] replaces |
| beforeFilesRemovedCallback(files, allFiles) -> bool    | beforeFilesRemoveCallback({ files, allFiles }) |
|                                                        |   ONLY false cancels (undefined now continues) |
| validateCallback(file, existingFiles)                  | validateCallback({ file, existingFiles })     |
| fileIconCallback(file)                                 | getFileIconCallback({ file })                 |
| uploadFileCallback(file, onProgress, signal, context)  | uploadFileCallback({ file, signal, setProgress, startBytes, |
|                                                        |   startPercent, metadata, setMetadata, uploadMetadata }) |
| picker uploadCallback / FileState.uploadCallback /     | uploadFileCallback (same ctx)                 |
|   addFiles(files, { uploadCallback })                  |                                               |
| persistStateCallback(key, state) / loadStateCallback(key) | ({ key, state }) / ({ key })               |
| renderFileItemCallback(file, { fileIndex, displayMode, isInPopover }) | ({ file, fileIndex, displayMode, isInPopover }) |
| renderListWrapperCallback(rowsHtml, files)             | ({ rowsHtml, files })                         |
| renderPromptCallback() / renderSummaryCallback(files)  | (ctx) / ({ files })                           |
| renderRolling*Callback(args) - config only             | same ctx (args.controller), now element inputs |
| indicator render*Callback(args)                        | names unchanged; args.controller replaces args.store |
| customStylesCallback()                                 | getCustomStylesCallback(ctx)                  |

Before:
dz.uploadFileCallback = async (file, onProgress, signal, context) => { ... onProgress(50) ... };
After:
dz.uploadFileCallback = async ({ file, setProgress, signal, startBytes, metadata, setMetadata }) => { ... setProgress(50) ... };

STEP 5: STRUCTURAL ROW BUTTONS
------------------------------
Built-in controls use data-dz-action (data-action is reserved):
  data-action="remove"      -> data-dz-action="remove"
  data-action="row-action"  -> data-dz-action="row-action"
  (new)                        data-dz-action="cancel"

STEP 6: CANCEL RULE
-------------------
- cancelFile(id) now returns Promise<void>; applies to uploading / pending /
  paused. Running handler -> status 'cancelling', signal aborts, waits
  cancel-timeout (default 2000 ms). Settled -> 'cancelled'; timeout ->
  cancel-timeout-behavior: error (default; file.error 'cancel-timeout') |
  remove. Late results ignored.
- FileStatus gains 'cancelling'. Handle it in switch statements.
- New: beforeFilesCancelCallback({ files, allFiles }), cancelAll(),
  file-cancel event, OverallProgress.pendingCount / cancellingCount.
- Row buttons split: Cancel (circle-slash) vs Remove (x). Before, x on an
  uploading row cancelled it and a second x removed it. Now x always removes
  (cancelling first). New item-controls token `cancel`; glyph inputs
  cancel-icon / remove-icon; CANCEL_ICON export.
- Removing a running file cancels it first; removeFile / removeFiles / clear
  resolve after that.
- Retry / resume of a cancelled file restarts from 0 (retryFile used to keep
  the old progress).

STEP 7: LABELS REPLACE TEXT ATTRIBUTES
--------------------------------------
| Removed                                  | Use                               |
|------------------------------------------|-----------------------------------|
| prompt-text / promptText                 | labels.prompt                     |
| hint-text / hintText                     | labels.hint                       |
| drag-active-text / dragActiveText        | labels.dragActive                 |
| no-file-chosen-text / noFileChosenText   | labels.noFileChosen               |
| overlay-text / overlayText               | labels.overlay                    |
| select-files-text / selectFilesText      | labels.selectFiles                |
| STATUS_LABELS export                     | labels.statusPending ... statusCancelled |
| ACTION_LABELS export                     | labels.pauseFile / resumeFile / retryFile |

<!-- before -->
<web-dropzone prompt-text="Drop invoices" hint-text="PDF only" display-mode="list"></web-dropzone>
<!-- after -->
<web-dropzone labels='{"prompt":"Drop invoices","hint":"PDF only"}' display-mode="list"></web-dropzone>

Also moved into labels: empty-message -> labels.noData, summary-template ->
labels.summary; the satellites' label / hint / no-file-chosen-text / list
empty-message / indicator label attributes -> each satellite's own `labels`
(merged over the store's). Popover, limits line, progress strip, indicator
and validation texts are labels keys too (see labels-i18n.txt).

STEP 8: LIFECYCLE
-----------------
- A DOM move no longer rebuilds the store (files and uploads survive, `ready`
  fires once).
- Removing the element from the page now cancels its uploads and destroys the
  store (one frame after disconnect). Opt out: keep-alive-when-removed.
- Mode-flip rebuild now reports dropped files (file-remove + change).
- `ready` is core's: fired ONCE after the first build (not after a mode-flip
  rebuild / re-add); data-ready -> `ready` attribute + :state(ready);
  whenReady(); `defer` + release() hold the first build.
- el.destroy() is core's and FINAL: aborts uploads, clears the form value, the
  element stays inert (re-inserting it builds nothing - create a new one).

STEP 9: NEW API
---------------
removeFiles(ids, { confirm? }), cancelAll(), el.controller, beforeFilesCancelCallback,
file-cancel, labels, cancel-timeout, cancel-timeout-behavior, cancel-icon,
remove-icon, keep-alive-when-removed, readonly, fileIcons + getFileIconCallback,
FILE_TYPE_ICONS / UI_ICONS, <web-dropzone-picker>.openFileDialog().

STEP 10: THEMING
----------------
- Dark/light follows the page via data-context-theme (from
  web-components-core), not :host-context(); NO prefers-color-scheme rule -
  declare html { color-scheme: light dark } to follow the OS. Themed wrappers
  need theme-source="closest". Dark mode flips color-scheme only.
- Reads --base-primary-* instead of --base-accent-*:
  --base-accent-color -> --base-primary-color (+ -hover / -active),
  --base-accent-color-light -> --base-primary-bg-subtle,
  --base-text-color-on-accent -> --base-on-primary-text-color.
  Other 2.0.0 names: --base-outline-width, --base-focused-outline,
  --base-*-text-color, --base-on-<role>-text-color, --base-input-text-color.
- Shadows use --base-shadow-color.
- All icons are Lucide SVGs (emoji defaults gone); --dz-icon-remove is Lucide x.
- Component --dz-*-accent-* token names unchanged.

STEP 11: TYPE RENAMES
---------------------

FileDeletedEventDetail -> FileDeleteEventDetail, FileStatusChangedEventDetail
-> FileStatusChangeEventDetail, FileUpdatedEventDetail -> FileUpdateEventDetail,

=====================================================================
1.0.0-rc01 -> 1.0.0-rc02   (additive)
=====================================================================
No breaking changes. New: controls / item-controls allowlists, grid-layout
(uniform | natural), grid-status (badge | overlay),
--dz-preview-item-object-fit, show-thumbnails for badges and detailed.
Fix: --dz-* set on <web-dropzone> now reach the internal satellites (they are
marked `managed`). If you worked around that by theming satellites inside
the shadow root, remove the workaround.

=====================================================================
pre-rc builds -> 1.0.0-rc01
=====================================================================
- Built on web-components-core BlissElement:
  * property writes coalesce on a microtask - `await el.whenSettled()` before
    reading derived state (methods flush, so el.prop = x; el.method() works);
  * el.setAttributes({...}) takes camelCase config keys and flushes; el.batch(fn);
  * optional-string getters return null (not '') when unset.
- Attribute renames: max-size -> max-file-size, max-files -> max-file-count
  (config maxSize -> maxFileSize, maxFiles -> maxFileCount).
- list-appearance="chips" -> "badges" (classes .dz__chip* -> .dz__badge*,
  --dz-chip-* -> --dz-badge-*, --dz-chips-gap -> --dz-badges-gap).
- Hidden filename inputs removed: forms submit real File blobs via
  ElementInternals; value-format kept but inert.
- Config keys: multiple -> isMultiple, disabled -> isDisabled,
  filesInside -> isFilesInside (attributes unchanged; the el.multiple-style
  aliases were removed in rc03 - see STEP 8b).
- Removed notification callbacks addCallback, removeCallback, changeCallback,
  rejectCallback, retryCallback, uploadedCallback, deleteCallback - use events.
- removeFile / clear / addFiles return Promises.
- CSS partials lost the "_" prefix (src/css/_variables.css -> variables.css);
  @layer variables, component, overrides; --base-* names moved to the
  canonical set (--base-input-background -> --base-main-bg, --base-primary-bg
  -> --base-elevated-bg, --base-primary-bg-hover -> --base-hover-bg).
- .dz__dropzone card chrome moved to .dz__dropzone--card.
- Package split: @keenmate/web-dropzone-core (headless) +
  @keenmate/web-dropzone (renderer).
(Event names / callback signatures introduced in this era were renamed again
in rc03 - apply the rc03 steps afterwards.)
