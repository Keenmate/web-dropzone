ADVANCED PATTERNS
=================

1. HEADLESS STORE + FRAMEWORK-RENDERED UI
-----------------------------------------
<web-dropzone id="store" render-mode="headless" multiple max-file-count="6"></web-dropzone>
<web-dropzone-picker for="store"></web-dropzone-picker>     <!-- optional -->

React:
function Uploads() {
  const ref = useRef(null);
  const [files, setFiles] = useState([]);
  useEffect(() => {
    const dz = ref.current;
    const onTick = (e) => setFiles(e.detail.files);       // rAF-coalesced snapshot
    dz.addEventListener('files-change', onTick);
    dz.uploadFileCallback = upload;
    return () => dz.removeEventListener('files-change', onTick);
  }, []);
  return (<>
    <web-dropzone ref={ref} render-mode="headless" />
    {files.map(f => (
      <div key={f.id}>{f.name} {Math.round(f.progress)}% {f.status}
        <button onClick={() => ref.current.cancelFile(f.id)}>Cancel</button>
        <button onClick={() => ref.current.removeFile(f.id, { confirm: true })}>Remove</button>
      </div>))}
  </>);
}

- files-change gives { changedIds, files } at most once per frame - diff by id.
- getFiles() / detail.files are copies of the list; FileState objects are
  live store objects - treat them as read-only.
- Feed files in with controller.addFiles(fileList) from your own <input> /
  drop handler; validation and gates still apply.

Without any custom element (pure JS):
import { DropzoneEngine } from '@keenmate/web-dropzone-core';
const engine = new DropzoneEngine(hostDiv, { maxFileCount: 6, uploadFileCallback: upload });
hostDiv.addEventListener('files-change', (e) => render(e.detail.files));
engine.controller.addFiles(input.files);
engine.destroy();                         // when done

2. MODE B - ONE QUEUE, PER-PICKER ENDPOINTS
-------------------------------------------
<web-dropzone id="cloud"></web-dropzone>
<web-dropzone-picker id="pub"  for="cloud" selector-appearance="button" labels='{"selectFiles":"Public"}'></web-dropzone-picker>
<web-dropzone-picker id="priv" for="cloud" selector-appearance="button" labels='{"selectFiles":"Private"}'></web-dropzone-picker>
<web-dropzone-list for="cloud" list-appearance="detailed"></web-dropzone-list>

pub.uploadFileCallback  = (ctx) => putTo('/public', ctx);
priv.uploadFileCallback = (ctx) => putTo('/private', ctx);
priv.uploadMetadata = { acl: 'private' };

async function putTo(url, { file, signal, setProgress, uploadMetadata }) {
  const body = new FormData();
  body.append('file', file);
  if (uploadMetadata) body.append('meta', JSON.stringify(uploadMetadata));
  const res = await fetch(url, { method: 'POST', body, signal });
  if (!res.ok) throw new Error(res.statusText);
  setProgress(100);
}

Per-file handler wins: file.uploadFileCallback ?? store.uploadFileCallback.
Programmatic: cloud.controller.addFiles(files, { uploadFileCallback, uploadMetadata }).
The progress strip's Pause/Resume/Cancel all need a store-level handler.

3. PERSISTED UI STATE (storage-key)
-----------------------------------
<web-dropzone display-mode="compact" storage-key="mail-attachments"></web-dropzone>

What is persisted: DropzoneState = { popoverWidth?, popoverHeight? } - the
user's last popover resize (debounced). Restored when the popover opens.
Default sink: localStorage key `dz-state:<storage-key>`. Unset / empty
storage-key disables persistence. Use distinct keys per dropzone.
FILES ARE NOT PERSISTED.

Custom sink (e.g. server-side user prefs):
dz.persistStateCallback = async ({ key, state }) => {
  await fetch(`/api/prefs/${key}`, { method: 'PUT', body: JSON.stringify(state) });
};
dz.loadStateCallback = async ({ key }) => {
  const r = await fetch(`/api/prefs/${key}`);
  return r.ok ? r.json() : null;
};
persistStateCallback receives the FULL merged state each time. Errors are
swallowed (logged on DROPZONE:UI); the component keeps in-memory state.

4. RESUMABLE UPLOADS
--------------------
Contract: ctx.startBytes / startPercent = last reported progress;
ctx.setMetadata({...}) stashes server state that survives pause / retry;
ctx.metadata returns it. See the full tus-style handler in upload-pipeline.txt.

Rules to remember:
- pause -> resume and retry-after-error keep progress (startBytes > 0).
- retry / resume of a CANCELLED file restarts at 0 but metadata is kept:
  create a new server upload when startBytes === 0.
- progress-mode="pessimistic" when you only report acknowledged bytes.
- Chunk with file.slice(offset, offset + size) and pass ctx.signal to fetch.
- Clean partial uploads in onFileCancel / onFileDelete (events-callbacks.txt).

5. PRE-UPLOAD DECISIONS (STAGE, ASK, THEN UPLOAD)
-------------------------------------------------
SharePoint-style name collisions (see examples-sharepoint-collisions.html):

<web-dropzone id="dz" render-mode="structural" display-mode="list" auto-upload="false"></web-dropzone>

- auto-upload="false": files stay 'pending'.
- files-change: batch-ask the server which names exist.
- renderFileItemCallback returning an HTMLElement: each row owns its
  Overwrite / Rename / Skip controls; state survives ticks via file-row-update.
- Skip -> dz.removeFile(id); Rename -> remove + addFiles(new File([f.file], newName));
  then dz.uploadFile(id) per decided row or dz.uploadAll().

Simpler gate for "ask before anything enters the list":
dz.beforeFilesAddCallback = async ({ files }) => (await ask(files)) ? undefined : false;

6. RECIPES OVER controls / item-controls + change
-------------------------------------------------
Show the overall progress strip only for 3+ files:
dz.onChange = ({ files, element }) => {
  element.controls = files.length >= 3 ? null : ['picker', 'list'];   // null = everything
};

Hide per-row progress once everything is done:
dz.onFileStatusChange = ({ controller, element }) => {
  const p = controller.getOverallProgress();
  element.itemControls = p.completedCount === controller.getFiles().length
    ? ['icon', 'name', 'size', 'remove'] : null;
};

Config changes do not fire `change` (no feedback loop).

7. MULTIPLE INDEPENDENT DROPZONES / SPLIT OVERLAY
-------------------------------------------------
Each <web-dropzone> is its own store. Two hidden stores can target two halves
of one editor for "attach as file" vs "share as link":

<div class="editor-shell" style="position:relative">
  <div contenteditable="true" class="wysiwyg"></div>
  <!-- invisible split grid over the editor; pointer-events:none keeps typing working -->
  <div style="position:absolute;inset:0;display:grid;grid-template-columns:1fr 1fr;pointer-events:none">
    <div id="half-left"></div><div id="half-right"></div>
  </div>
</div>
<web-dropzone-list for="attach" list-appearance="badges"></web-dropzone-list>
<web-dropzone-list for="share"  list-appearance="badges"></web-dropzone-list>

<!-- hidden stores (no display attrs -> headless); only their overlays render -->
<web-dropzone id="attach" style="display:none; --dz-overlay-bg: rgba(0,120,212,.92)"
  overlay-target="half-left" max-file-count="5" labels='{"overlay":"Attach as file"}'></web-dropzone>
<web-dropzone id="share" style="display:none; --dz-overlay-bg: rgba(20,184,166,.92)"
  overlay-target="half-right" labels='{"overlay":"Share as link"}'></web-dropzone>

The drag overlay works in headless mode too. Use overlay-enter /
overlay-leave to update overlay text per zone (e.g. remaining quota). When one
overlay ends (drop / Escape), its siblings tear down too.
(Full version: examples-split-overlay.html.)

8. IMPERATIVE CODE AFTER PROPERTY WRITES
----------------------------------------
dz.maxFileCount = 1;
dz.addFiles(files);              // OK: element methods flush pending writes
dz.controller.addFiles(files);   // OK: el.controller flushes too
const cfg = dz.controller.getConfig();  // OK
// reading derived DOM / satellites right after a write: await dz.whenSettled()

9. LIFECYCLE: MOVE vs REMOVE
----------------------------
- Moving the element (appendChild elsewhere, reorder): store kept, uploads
  continue, open popover kept, no new `ready`.
- Removing it (still detached one frame later): uploads cancelled by the cancel
  rule (file-cancel fires, no gate), then the store is destroyed. Re-adding
  later builds an empty store and fires `ready`.
- keep-alive-when-removed: nothing is torn down while detached - e.g. a
  dropzone inside a tab panel that is detached when hidden. Call destroy()
  yourself when the view is really gone.

SPA route change that should keep uploading in the background:
<web-dropzone id="bg" render-mode="headless" keep-alive-when-removed></web-dropzone>
plus a <web-dropzone-indicator for="bg"> in the app shell (keep the store in
the shell so the indicator can resolve it).

10. CUSTOM SATELLITE (VANILLA)
------------------------------
class UploadCounter extends HTMLElement {
  connectedCallback() {
    this.store = document.getElementById(this.getAttribute('for'));
    this.onTick = () => {
      const p = this.store.controller.getOverallProgress();
      this.textContent = p.totalBytes ? `${Math.round(p.percent)}%` : '';
    };
    for (const n of ['ready', 'files-change', 'change']) this.store.addEventListener(n, this.onTick);
    if (this.store.controller?.isReady) this.onTick();
  }
  disconnectedCallback() {
    for (const n of ['ready', 'files-change', 'change']) this.store.removeEventListener(n, this.onTick);
  }
}
customElements.define('upload-counter', UploadCounter);

11. RESTRICTING ACTIONS
-----------------------
- Lock completed files: allow-uploaded-file-removal="false".
- Confirm destructive removes only for uploaded files:
  dz.beforeFilesRemoveCallback = ({ files }) =>
    files.some(f => f.status === 'complete') && !confirm('Delete uploaded files?') ? false : undefined;
- Prevent cancelling near completion:
  dz.beforeFilesCancelCallback = ({ files }) => files.every(f => f.progress < 95) ? undefined : false;
