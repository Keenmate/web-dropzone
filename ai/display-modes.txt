DISPLAY MODES & APPEARANCE
==========================

OPERATING MODE (mode)
---------------------
render-mode="bulk"        component renders everything; style via CSS variables.
                   Render callbacks are IGNORED even if set.
render-mode="structural"  component decides when/what to render; YOU supply HTML via
                   render callbacks (custom-rendering.txt).
render-mode="headless"    renders nothing; store + events only (satellites or your
                   framework render).

When `mode` is absent it is inferred:
  display-mode / selector-appearance / list-appearance present -> bulk
  none present                                                 -> headless
Inference never yields "structural" - that needs an explicit render-mode="structural".

Changing mode (or any of the three trigger attributes) so the resolved mode
flips REBUILDS the store: every file is removed and reported (file-remove per
file + one change), running uploads get their abort signal, `ready` fires again.

THREE ORTHOGONAL AXES
---------------------
selector-appearance  what the user clicks / drops onto
list-appearance      how picked files are shown
card-size            density of the card selector

selector-appearance:
  card     bordered drop area: icon + prompt (+ hint, + browse button when big)
  button   single "Select files" button with count badge (no drop styling;
           drag-drop onto it still works)
  minimal  icon-only button with count badge
  native   mimics <input type="file">: button + "No file chosen" / filename /
           "N files chosen" text. Drag-drop still works.

list-appearance:
  list      simple rows
  detailed  rows with icon, name, size, type
  grid      image thumbnails in a grid (see grid-layout / grid-status)
  badges    inline pills (shares web-multiselect's badge look)
  rolling   one "front" file row + queue button that opens the full list
  popover   list hidden in a popover opened from a summary line / the selector
  none      no list (read dz.files yourself)

card-size: minimal (thin single row) | compact (default) | big (tall, large
icon, browse button labelled by labels.selectFiles, hint).

DISPLAY-MODE SHORTHAND
----------------------
display-mode expands to preset axes; explicit axis attributes win.

  display-mode   selector  list       card-size
  list (default) card      list       compact
  detailed       card      detailed   compact
  grid           card      grid       compact
  compact        card      popover    compact

<web-dropzone display-mode="grid" accept="image/*"></web-dropzone>
<web-dropzone selector-appearance="button" list-appearance="badges"></web-dropzone>
<web-dropzone selector-appearance="native" list-appearance="none"
              labels='{"selectFiles":"Choose Files"}'></web-dropzone>
<web-dropzone list-appearance="grid" card-size="big"
              labels='{"prompt":"Upload your portfolio","hint":"PNG or JPG"}'></web-dropzone>

GRID OPTIONS
------------
grid-layout="uniform"   equal-size responsive tiles (default);
                        crop vs fit via --dz-preview-item-object-fit: cover|contain
grid-layout="natural"   justified gallery: rows share --dz-preview-row-height,
                        tiles keep each image's aspect ratio
grid-status="badge"     small corner status glyph on finished tiles (default)
grid-status="overlay"   light veil + big centred check/error glyph on complete /
                        error tiles (click-through; uploading keeps its spinner)

THUMBNAILS (show-thumbnails)
----------------------------
Tri-state:
  unset (default)        auto: thumbnails for grid, file-type icons elsewhere
  show-thumbnails        always <img> for images (list, detailed, badges too)
  show-thumbnails="false" never thumbnails
Property: dz.isThumbnailsShown = true | false | undefined.
Previews are generated asynchronously (FileReader -> data URL); the row repaints
on `file-update`. Hide the icon slot entirely with e.g.
web-dropzone { --dz-badge-icon-size: 0; }.

FILES INSIDE THE DROP AREA (files-inside)
-----------------------------------------
<web-dropzone files-inside display-mode="list"></web-dropzone>
<web-dropzone files-inside display-mode="grid" accept="image/*"></web-dropzone>

Only effective with a card selector and both picker and list visible;
otherwise it falls back to the normal stacked layout.

COMPACT / POPOVER
-----------------
<web-dropzone display-mode="compact"
              summary-template="{count} file(s), {size}"
              popover-placement="bottom-start"></web-dropzone>

- Card + popover: a summary line ("{count} file(s), {size}" by default) is the
  trigger. With button / minimal selectors the selector itself is the trigger.
- summary-template placeholders: {count}, {size} (each replaced once).
- popover-placement: top|bottom|left|right with optional -start/-end
  (floating-ui placement; default bottom-start). Positioned via core
  /positioning (flip + shift + viewport caps, autoUpdate).
- Popover contents: header with "Add more" (hidden while disabled) and
  "Clear all" (goes through beforeFilesRemoveCallback), a limits hint line
  (derived from accept / size / count caps when labels.hint is empty), the
  file table, and a totals footer.
- Closes on outside click and Escape; closes itself when the last file is removed.
- User-resizable (--dz-popover-resize: both). With storage-key the size is
  persisted (advanced-patterns.txt).
- Popover appearance renders nothing while the list is empty.

ROLLING
-------
<web-dropzone list-appearance="rolling" rolling-rotation="slide-in"></web-dropzone>

Shows the highest-priority active file; when it finishes the next one rolls in.
rolling-rotation: horizontal (conveyor) | vertical (stack) | slide-in (default).
The queue button opens the popover with the full list. Structural mode can
replace parts via renderRolling{Body,FileInfo,Progress}Callback
(custom-rendering.txt).

COMPOSITION: controls / item-controls
-------------------------------------
Plyr-style comma-separated allowlists. Absent = render everything. Unknown
tokens are dropped; tokens are case-insensitive.

controls (top-level surfaces):
  picker             the selector
  list               the inline file list
  overall-progress   the aggregate progress strip

<web-dropzone display-mode="list" controls="list,overall-progress"></web-dropzone>

item-controls (per-row parts):
  icon       file-type icon / thumbnail
  name       file name
  size       human-readable size (detailed)
  type       MIME type (detailed)
  progress   per-row bar + percent
  status     status icon / pill
  action     pause / resume / retry button
  cancel     Cancel button (circle-slash glyph)
  remove     Remove button (x glyph)

<web-dropzone display-mode="detailed" item-controls="icon,name,progress,remove"></web-dropzone>

Parts an appearance doesn't have are ignored (grid has no size/type, badges have
no progress). Property form: dz.itemControls = ['name', 'remove'].

ROW BUTTONS: CANCEL vs REMOVE
-----------------------------
Every row (list, detailed, grid, badges, popover, <web-dropzone-list>) has:

  Cancel (circle-slash)  aria-label "Cancel <name>". Offered for uploading /
                         paused files, and for queued files when an upload
                         handler will run them. Asks beforeFileCancelCallback.
                         The row STAYS with status "cancelled" and a Retry action.
  Remove (x)             aria-label "Remove <name>". Always offered (except
                         completed rows when allow-uploaded-file-removal="false"). A
                         running upload is cancelled first, then the file is
                         removed. Asks beforeFilesRemoveCallback.

While a cancel waits for the handler the row reads "Cancelling..." with its
buttons disabled. Glyphs are raw-HTML inputs (NOT sanitized):

<web-dropzone display-mode="list"
  cancel-icon="<svg ...>...</svg>"
  remove-icon="&times;"></web-dropzone>

allow-uploaded-file-removal="false": hides Remove on completed rows (space reserved,
out of the tab order). removeFile(id) still works programmatically.

OTHER LIST KNOBS
----------------
max-visible-file-count="7"      rows shown before a "Show N more" / "Show less"
                           toggle (badges: "+N" pill). 0 = show all. Default 7.
empty-message="..."        text when the list is empty (default "No files selected")
sink-completed      completed files move to the end of the rendered list
sink-completed-delay    ms a completed row stays put first (default 1500)
                           (visual only; dz.files order and events unchanged)
icon="..."                 prompt icon for card / minimal (raw HTML; default Lucide cloud-upload)

DRAG OVERLAY (overlay-target)
-----------------------------
Show a full overlay over another element while files are dragged over it:

<form id="mail-form">
  <textarea name="body"></textarea>
  <web-dropzone display-mode="compact"
                overlay-target="mail-form"
                overlay-icon="<svg ...></svg>"
                labels='{"overlay":"Drop attachments onto the form"}'></web-dropzone>
</form>

- overlay-target: element id or CSS selector ("#mail-form", ".editor"), id tried
  first. Property may be an HTMLElement: dz.overlayTarget = editorEl.
- overlay-icon: raw HTML (default Lucide upload). Text: labels.overlay.
- Dropping on the overlay adds the files to this dropzone.
- Events: overlay-enter / overlay-leave ({ overlayElement }) on the dropzone.
  Hovered overlay gets class dz__overlay--hover.
- The overlay goes away on drop, Escape (in-page drags), dragend, or ~350 ms
  without dragover (external drags).
- Several dropzones may target adjacent regions (split overlay); when one
  overlay ends, the others tear down too.

overlay-enter use:
dz.onOverlayEnter = ({ overlayElement, controller }) => {
  const left = 5 - controller.getFiles().length;
  overlayElement.querySelector('.dz__overlay__text').textContent = `${left} slots left`;
};
(overlay markup: .dz__overlay__content > .dz__overlay__icon + .dz__overlay__text -
internal class names, not a versioned API)

DISABLED
--------
<web-dropzone disabled ...>  or an ancestor <fieldset disabled>.
Disabled blocks clicks and drops; dz.disabled reports the element's own value.
