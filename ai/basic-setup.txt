BASIC SETUP
===========

<web-dropzone> is a file-selection + upload web component (Shadow DOM,
form-associated, built on @keenmate/web-components-core BlissElement).
One element is the STORE (files, validation, upload queue). It can render
its own UI (picker + list + progress strip) or none at all (headless) and let
satellite elements render instead.

INSTALLATION
------------
npm install @keenmate/web-dropzone

Two packages:
- @keenmate/web-dropzone       the custom elements + CSS (bundles the core)
- @keenmate/web-dropzone-core  headless DropzoneEngine (no DOM, no CSS)

Most apps need only @keenmate/web-dropzone.

REGISTER THE ELEMENTS
---------------------
import '@keenmate/web-dropzone';

This one import defines all five custom elements:
  <web-dropzone>            the store (+ built-in UI)
  <web-dropzone-picker>     satellite: file selector
  <web-dropzone-list>       satellite: file list
  <web-dropzone-indicator>  satellite: floating status chip + drawer
  <web-dropzone-progress>   satellite: aggregate progress strip

Styles are injected into each shadow root automatically.

FIRST DROPZONE
--------------
IMPORTANT: a bare <web-dropzone></web-dropzone> renders NOTHING. With no
`mode` attribute the mode is inferred:
  - any of display-mode / selector-appearance / list-appearance present -> "bulk"
    (the element renders its own UI)
  - none present -> "headless" (store only; satellites render)

So for a self-contained dropzone, always set one of the display attributes:

<web-dropzone display-mode="list"></web-dropzone>

Or explicitly:

<web-dropzone render-mode="bulk"></web-dropzone>      <!-- display-mode defaults to "list" -->

COMMON ATTRIBUTES
-----------------
<web-dropzone
  display-mode="detailed"          list | detailed | grid | compact
  accept="image/*,.pdf"            MIME types / extensions, comma-separated
  max-file-size="5MB"              bytes, or "300 kB", "1.5GB", "5M" (1024-based)
  max-file-count="10"              0 = unlimited
  multiple                         default true; multiple="false" = single file
  name="attachments"               form field name (submits real File blobs)
  disabled>
</web-dropzone>

Byte inputs (max-file-size, min-file-size, max-total-size) accept plain integers
or a number + unit: B, K/KB, M/MB, G/GB, T/TB (case-insensitive, binary units).
An unparsable value keeps the previous value (warns).

READING FILES
-------------
const dz = document.querySelector('web-dropzone');

dz.files                 // FileState[] snapshot
dz.getFile(id)           // FileState | undefined
dz.controller.getFiles() // same, via the public facade

FileState (key fields):
{
  id: string,            // generated, stable for the file's lifetime
  file: File,            // the native File
  name, size, type,
  status: 'pending' | 'uploading' | 'paused' | 'cancelling'
        | 'complete' | 'error' | 'cancelled',
  progress: number,      // 0-100
  error?: string,
  previewUrl?: string,   // data URL for images (async)
  downloadUrl?: string,  // from the upload handler's result
  metadata?: object      // server-side info (upload result / ctx.setMetadata)
}

LISTENING
---------
dz.addEventListener('change', (e) => {
  console.log('Files now:', e.detail.files);
});

dz.addEventListener('files-reject', (e) => {
  for (const { file, validation } of e.detail.rejectedFiles) {
    console.log(file.name, validation.code, validation.error);
  }
});

// Or the camelCase twin property (receives the same detail):
dz.onFileAdd = ({ file }) => console.log('added', file.name);

All events bubble and are NOT composed. See events-callbacks.txt.

UPLOADING (MINIMAL)
-------------------
Set uploadFileCallback and the component runs a worker pool for you:

dz.uploadFileCallback = async ({ file, signal, setProgress }) => {
  const body = new FormData();
  body.append('file', file);
  const res = await fetch('/api/upload', { method: 'POST', body, signal });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  setProgress(100);
  return { metadata: { serverId: await res.text() } };
};

Files auto-upload as they are added (auto-upload defaults to true).
Without uploadFileCallback the dropzone only collects files; the app drives
status via updateFileProgress / setFileStatus. See upload-pipeline.txt.

METHODS (ELEMENT)
-----------------
addFiles(files)                    Promise<void>
removeFile(id, { confirm? })       Promise<void>
removeFiles(ids, { confirm? })     Promise<void>
clear({ confirm? })                Promise<void>
getFile(id)                        FileState | undefined
updateFileProgress(id, percent)    void   (app-driven uploads)
setFileStatus(id, status, error?)  void   (app-driven uploads)
uploadAll() / uploadFile(id)       Promise<void>
pauseFile(id) / pauseAll()         void
resumeFile(id) / resumeAll()       Promise<void>
cancelFile(id) / cancelAll()       Promise<void>
retryFile(id) / retryAll()         void
destroy()                          tear the store down

el.controller (DropzoneController) has the same methods plus getFiles(),
getConfig(), getOverallProgress(), and isReady. See typescript-types.txt.

PROPERTIES
----------
Every input has a property named after its config key (camelCase), e.g.
dz.accept, dz.maxFileSize, dz.maxFileCount, dz.labels, dz.cancelTimeout,
dz.uploadFileCallback. Back-compat boolean aliases:

dz.multiple          <-> multiple            (isMultiple)
dz.disabled          <-> disabled            (isDisabled)
dz.isFilesInside       <-> files-inside        (isFilesInside)
dz.isThumbnailsShown    <-> show-thumbnails     (tri-state: undefined = auto)
dz.shouldAutoUpload        <-> auto-upload         (shouldAutoUpload)
dz.isUploadedFileRemovalAllowed <-> allow-uploaded-file-removal  (isUploadedFileRemovalAllowed)

PROPERTY WRITES ARE COALESCED
-----------------------------
Property/attribute changes apply on a microtask (core BlissElement). Methods
flush first, so `dz.maxFileCount = 3; dz.addFiles(files)` works. To read
derived state right after a write:

dz.maxFileCount = 3;
await dz.whenSettled();

Batch several inputs synchronously:
dz.setAttributes({ maxFileCount: 3, accept: 'image/*' });   // camelCase keys
dz.batch(() => { dz.accept = '.pdf'; dz.maxFileSize = 1048576; });

READY
-----
The store is built on first connect. `ready` fires then (and again after a
rebuild caused by a mode flip); `data-ready` is set on the next frame
(useful for FOUC-hiding CSS: web-dropzone:not([data-ready]) { visibility: hidden }).

dz.addEventListener('ready', ({ detail }) => detail.controller.getFiles());
dz.controller.isReady   // true once built

BROWSER / SSR
-------------
- Requires Custom Elements v1, Shadow DOM, ElementInternals (form association).
  Without ElementInternals the form value is a no-op; dz.files still works.
- SSR-safe import (BlissElement stubs HTMLElement on the server); elements
  register only when `customElements` exists.
