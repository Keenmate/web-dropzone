KEYBOARD NAVIGATION & ACCESSIBILITY
===================================

This describes what is implemented today. The dropzone relies on native
controls (<input type="file">, <button>) rather than custom key handling; there
are only a few explicit key bindings.

KEY BINDINGS
------------
| Where                          | Key            | Action                          |
|--------------------------------|----------------|---------------------------------|
| Card selector (focused input)  | Enter / Space  | open the file dialog (native)   |
| Button / minimal / native      | Enter / Space  | open the file dialog (<button>) |
| Any row button                 | Enter / Space  | Cancel / Remove / Pause /       |
|                                |                | Resume / Retry (native button)  |
| Compact summary line           | Enter / Space  | toggle the popover              |
| Popover (open)                 | Escape         | close the popover               |
| Drag overlay (in-page drag)    | Escape         | remove the overlay              |
| <web-dropzone-list> summary    | Enter / Space  | fire `summary-activate`         |
| Indicator chip (drawer="auto") | Enter / Space  | toggle the drawer (<button>)    |
| Tab / Shift+Tab                |                | move between the controls above |

Not implemented: arrow-key navigation between rows, roving tabindex, Delete
key to remove, Escape for the indicator drawer, focus trap / focus return for
the popover or drawer. External file drags cannot be cancelled by Escape
(the OS swallows the key); the overlay closes ~350 ms after the drag stops.

TAB ORDER
---------
One tab stop per selector:
- card: the visually hidden <input type="file"> is the keyboard control; it is
  named after the prompt (aria-label = labels.prompt, or the picker's `label`).
  The card shows a focus ring via :focus-within.
- button / minimal / native: the visible <button> is the tab stop; the hidden
  input has tabindex="-1" aria-hidden="true".
Then each row's buttons in DOM order. Buttons that are not offered for the
current state (e.g. Cancel on a completed file, Remove on a completed file with
allow-uploaded-file-removal="false") stay in the layout but get tabindex="-1"
aria-hidden="true".

ACCESSIBLE NAMES (from labels; see labels-i18n.txt)
---------------------------------------------------
Card / minimal selector     labels.prompt
Button / native selector    labels.selectFiles (visible text)
Row Cancel                  labels.cancelFile  'Cancel {name}'
Row Remove                  labels.removeFile  'Remove {name}'
Row action                  labels.pauseFile / resumeFile / retryFile
Status pill                 labels.statusAria  'Status: {status}'
                            ({status} = labels.status*; timed-out cancel ->
                            labels.cancelTimeout)
Bulk buttons                labels.pauseAll / resumeAll / cancelAll / retryAll

Fixed English names (not in labels): summary line "Click to view files"
(role="button", tabindex="0"), rolling queue button "Show full queue (N files)",
badges "+N" pill "Show N more" / "Show fewer", indicator chip "Upload status",
drawer "Upload queue" (role="dialog"), drawer close "Close", spinner "Uploading".

ROLES & STATES
--------------
- Overall progress bar: role="progressbar" aria-valuemin="0"
  aria-valuemax="100" aria-valuenow (updated per tick).
- Indicator with drawer="off": <div role="status"> (polite live region semantics).
- Cancelling rows: buttons get `disabled` while the cancel waits.
- Disabled dropzone (disabled attribute or disabled <fieldset>): inputs and
  buttons are disabled; drops are ignored.
- There is no aria-live announcement for adds / rejects / completion. Announce
  from events if you need it:

  const live = document.getElementById('sr-status');   // <div aria-live="polite" class="sr-only">
  dz.onFilesReject = ({ rejectedFiles }) =>
    live.textContent = rejectedFiles.map(r => `${r.file.name}: ${r.validation.error}`).join('. ');
  dz.onFileUploadComplete = ({ file }) => live.textContent = `${file.name} uploaded`;

DRAG AND DROP
-------------
Drag-and-drop is a pointer enhancement; every selector also opens the native
file dialog, so keyboard and screen-reader users can always add files.
Drop targets: the card, button, minimal and native selectors, and the
overlay-target overlay.

FOCUS STYLING
-------------
Focus rings are `outline: 2px solid var(--dz-accent-color); outline-offset: 2px`
on: buttons (:focus-visible), the card (:focus-within), the summary line and
the indicator chip. There is no dedicated focus variable - the ring follows
--dz-accent-color. To restyle it, inject CSS with getCustomStylesCallback
(reaches <web-dropzone>'s own shadow root only; see custom-rendering.txt).

PROGRAMMATIC FOCUS
------------------
The interactive elements live in shadow roots. To move focus to the selector
from outside, focus the element (if your layout makes it focusable) or open
the dialog directly:

document.querySelector('web-dropzone-picker').openFileDialog();

REDUCED MOTION
--------------
Rolling rotation and spinners are animation-based; set
--dz-rolling-animation-duration: 0s for reduced motion if needed:

@media (prefers-reduced-motion: reduce) {
  web-dropzone { --dz-rolling-animation-duration: 0s; }
}

TESTING CHECKLIST
-----------------
- Tab reaches the selector; Enter opens the dialog.
- Each row's Cancel / Remove buttons are reachable and named "<verb> <file>".
- Compact mode: Enter on the summary opens the popover; Escape closes it.
- min-file-count: submitting a short form shows the native validation message.
