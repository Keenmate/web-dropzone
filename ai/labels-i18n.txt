LABELS & I18N
=============

EVERY UI string the dropzone and its satellites render by themselves comes
from ONE input: `labels`. It is a PARTIAL object merged per
key over the built-in English DEFAULT_LABELS. Placeholders in {braces} are
filled at render time.

Keys are FLAT `<elementType>.<name>` (core /locale): the element type says
where the text is SHOWN - buttons (visible caption), tooltips (title),
ariaLabels (screen-reader only: aria-label, live announcements), headers,
labels (other visible text), messages (empty state / progress), errors
(validation / failure). A text shown on two surfaces has two keys sharing
the name (ariaLabels.cancelFile + tooltips.cancelFile). The FULL key
prefixes the component: web-dropzone.buttons.selectFiles; `labels` takes the
short or the full key.

SETTING LABELS
--------------
Property (object):
dz.labels = { 'ariaLabels.cancelFile': 'Zrusit {ctx.name}', 'labels.prompt': 'Pretahnete soubory sem' };

Attribute (JSON object of strings):
<web-dropzone display-mode="list"
  labels='{"labels.prompt":"Drop invoices here","labels.hint":"PDF up to 10 MB","buttons.selectFiles":"Browse"}'>
</web-dropzone>

- Per-key merge: keys you omit keep their English default.
- Live: changing labels re-renders the element and its satellites.
- A malformed attribute (not JSON, or any non-string value) warns and keeps
  the previous value. Absent / empty attribute -> built-in English.
- Assigning a new object replaces the previous overrides (no deep merge with
  the previous object) - spread it yourself:
    dz.labels = { ...dz.labels, 'ariaLabels.retryFile': 'Znovu {ctx.name}' };

PLACEHOLDERS — {ctx.*} (rulebook D-NC-24)
------------
A dynamic label gets its text spot's context as { ctx }; templates read {ctx.<path>}
(numbers locale-formatted). translateCallback gets the same object as params.ctx (raw numbers).
ctx.count = the number the text's noun agrees with — plural rules belong to the app's
i18n library: i18next.t(key, { ...params, count: params.ctx?.count }). No singular
"...One" keys; the English defaults put no plural noun after a number ("Files: 3").
Context types (exported from both packages):
  FileLabelContext           { name, size, type }       row buttons, errors.duplicate, announceRemoved
  RejectedFileLabelContext   + reason                   announceRejected
  StatusLabelContext         { status, statusName }     ariaLabels.status
  FileCountLabelContext      { count }                  filesChosen, fileCount, showMore (hidden rows),
                                                        showQueue, progressPaused/Failed, indicator*,
                                                        announceAdded, announceUploadDone
  SummaryLabelContext        { count, size, bytes }     labels.summary
  SizeLimitLabelContext      { size, bytes, left?, leftBytes? }  size limits + size errors
  CountLimitLabelContext     { count, left? }           count limits, errors.max/minFileCount
  ProgressCountsLabelContext { completed, total, uploadedSize, totalSize, count = total }
  UploadResultLabelContext   { done, failed, count = done + failed }  announceUploadFailed
Unknown placeholders are left as written. Only the keys above are looked up.

THE resolveLabel SEAM
---------------------
Every lookup goes through one function:

import { resolveLabel, DEFAULT_LABELS, createLabelFn } from '@keenmate/web-dropzone';

resolveLabel(sources, key, params?)
  sources = one labels object or an array (most specific first: a satellite's
  own labels, then its store's); the first that has key wins ->
  window.components.locale.labels['web-dropzone.<key>'] -> DEFAULT_LABELS[key],
  then {ctx.*} placeholders filled from params ({ ctx }).

resolveLabel({ 'ariaLabels.cancelFile': 'Stop {ctx.name}' }, 'ariaLabels.cancelFile', { ctx: { name: 'a.pdf' } })  // 'Stop a.pdf'
resolveLabel(null, 'ariaLabels.status', { ctx: { status: 'paused', statusName: 'Paused' } })              // 'Status: Paused'

const label = createLabelFn(() => dz.labels);    // bound lookup, reads live
label('buttons.retryAll');

Use these in custom satellites / render callbacks so your UI matches the
element's language.

PAGE-WIDE (core /locale)
------------------------
window.components.locale = {
  locale: 'cs-CZ',
  labels: {                                         // ONE flat dictionary of full keys
    'web-dropzone.labels.prompt': 'Přetáhněte soubory sem',
    'web-dropzone-indicator.headers.indicator': 'Fronta',   // that satellite only
  },
  translateCallback: ({ key, params }) => {
    const options = { ...params, count: params.ctx?.count };   // i18next plural keys _one / _few / _other
    return i18next.exists(key, options) ? i18next.t(key, options) : null;
  },
};
translateCallback gets the FULL key; null / undefined = not mine. It is never
asked for a key the instance set in its own labels.

Also exported from @keenmate/web-dropzone-core: defaultLabel, statusLabel(label,
status), fileStatusLabel(label, file) (returns labels.cancelTimeout for timed-out
cancels), isLabelsValue(value), fileLabelContext(file), types DropzoneLabels,
DropzoneLabelKey, DropzoneLabelOverrides, LabelFn, LabelParams + the *LabelContext types above.

SATELLITES
----------
Satellites read the BOUND STORE's labels. Every satellite also takes its OWN
`labels` (property or JSON attribute), merged per key ON TOP of the store's:
  <web-dropzone-picker for="dz" labels='{"labels.prompt":"Drop invoices","labels.hint":"PDF only"}'>
  <web-dropzone-picker for="dz" selector-appearance="button" labels='{"buttons.selectFiles":"Browse"}'>
  <web-dropzone-list for="dz" labels='{"messages.noData":"Nothing yet"}'>
  <web-dropzone-indicator for="dz" labels='{"headers.indicator":"Queue"}'>
  picker.labels = { 'labels.noFileChosen': 'Nic' };   // live
